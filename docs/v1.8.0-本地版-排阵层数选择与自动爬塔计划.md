## 一、需求拆解

1. **移除「跳过本层」全部逻辑**（排阵界面）—— 跳过已通关层与游戏根本（真打真赢）相悖。
2. **「前往第几层」改为三个从上往下的纵向框**：
   - **a. 下一层（绿框）**：难度正常，层 +1。
   - **b. 下五层（黄框）**：一场战斗代表五层——敌方强度 = 「实际五层后」×1.20；高级奖励概率 +10%（奖励基础 = 五层之和）。
   - **c. 自动爬塔（红框）**：剩余容错 ≥1 才可选；进入自动爬塔状态：先选 **c1 战略**（三选一，爬塔全程生效）、再选 **c2 预计胜率目标**（≥51% 可选）→ 飘出「挑战即将开始，准备迎接梦魇吧！全军突击（3秒）」→ **一次传送 ≤10 层结果**。每层实际难度比正常 +10%~15%、收益不变；某层失败则前端播放到那一场战斗后**扣一次挑战机会**；无失败则一直打到「预计胜率跌破目标阈值」的层。

## 三、设计明细

### A. 移除「跳过本层」（需求 1）

| 位置 | 改动 |
|---|---|
| `PreBattle.tsx` | 删 `canSkip` / `skip()` / ⏭ 按钮；`TutorialOverlay` 不再挂 `tut-prebattle-skip` |
| `packages/core/src/rules/index.ts` | 删 `skipLayer`（保留 `advanceLayer` 不动） |
| `packages/core/src/contract/index.ts` | 删 `skipLayer` 方法 |
| `LocalBackend.ts` / `RemoteBackend.ts` / mock-edge / Edge Function | 删 `skipLayer` handler |
| `tutorial.ts` | 删「跳过已通关层」教学点（含 layer5 教学浮层引用） |
| `integration.ts` | PRE_ANCHORS 去掉 `tut-prebattle-skip` |
| **e2e 驱动迁移** | 新增 core 纯函数 `advanceLayerTo(s, n)`（仅导航：layer=n + 重置每层旗标；无校验/无奖励/无 status 变更），契约与四端各加 `advanceLayerTo` 命令；3 个 e2e 脚本改用它（`{ layer: 999 }` → `{ layer: n }`） |

> 说明：`advanceLayerTo` 只是把 skipLayer 的「测试驱动」职责独立出来，玩家侧零暴露——UI 不再有任何跳过入口，核心规则也没有「跳过结算胜利」的能力。

### B. 三框层数选择（需求 2 入口，`IntermissionHub.tsx`）

- 把现有「前往第 N+1 层 →」单按钮换成**三个纵向框**（从上往下，间距 8px，全宽卡片）：
  - 🟢 **下一层**：`setLayer(layer+1)` → pre（行为同现状）。
  - 🟡 **下五层**：说明「敌方强度 ≈ 五层后 ×1.20 ｜ 高奖 +10% ｜ 奖励 = 五层之和」→ 直接进 `PreBattle`（带 `mode:'skip5'` 上下文）。
  - 🔴 **自动爬塔**：`run.failures < 2`（剩余容错 ≥1）才可点，否则置灰 + 提示「剩余容错为 0，无法自动爬塔」；点击进入 c1→c2 配置流。
- 布阵上下文：`PreBattle` 按当前 mode 渲染标题（「第 N+1 层（下五层挑战）」等），战斗与掉落走 `BattleMods`（见 C/D）。

### C. 下五层战斗（需求 2b）

- 新核心规则 `battle5(s)`（纯函数，Local/Remote 同一份）：
  - **敌方强度**：`enemyScale(s.layer+5)` 的基础上再 ×1.20（hp/dmg 同乘）。
  - **奖励**：`goldReward(layer+i)` 与 `rollDrops(layer+i)` 对 i=1..5 求和合并（箱子数 = 5 层各自 chestCount 之和；boss 判定按各层实际）。
  - **高奖 +10%**：临时掉落表——`equip_high` 0.20→0.25、`equip_rare` 0.10→0.15（高奖合计 0.30→0.40，其余档按比例归一）。⚠ 开放项 1。
  - 胜负：胜 → 快照层到 `min(layer+5, cap)`、发放奖励、进入休整；败 → `failures+1`（同普通战斗容错）。
- 前端：`PreBattle` 进入 `mode:'skip5'` 时 `genLayer` 用「目标层」出敌人/布阵预览，sim 构造时套 `BattleMods`。
- 新增 `BattleMods` 传参（`buildBattleSim` 第 6 参）：`{ enemyHpMult?, enemyDmgMult?, rewardHighBonus? }`——**不改战斗引擎核心**，只在构造时对 `enemyScale` 输出乘一次。

### D. 自动爬塔（需求 2c，核心）

**新核心纯函数 `autoClimb(s, opts)`**，`opts = { strategy: 'raidRear'|'steadyPush'|'breakThrough', winRateTarget?: number }`：

1. 逐层 `i = s.layer+1 .. s.layer+10`（封顶 `capFor(mode)`）：
   - 难度倍率：第 1 层 +10%，逐层线性到第 10 层 +15%：`climbMult(i) = 1.10 + 0.05 * (i-1)/9`（⚠ 开放项 4）。
   - 先算**预计胜率**：`predictWinRate(...)` < `winRateTarget` → **停在该层之前**（不打，标记 stopReason=winrate）。
   - 构造 sim（战略 buff + climbMult）→ quick-sim（引擎逐 tick 跑完，无渲染）→ win？
   - win → 记该层奖励（rollDrops/goldReward 照常）；lose → 停在该层，`failures+1`。
2. 返回 `AutoClimbResult`：`{ layers: [{layer, win, gold, drops}], finalLayer, stopReason: 'cap'|'winrate'|'fail', failLayer? }`——**一次性传送**：前端把奖励统一入 `pendingDrops`/`gold`，层直接跳到 `finalLayer`。
3. 失败演示：`stopReason='fail'` 时前端**从起点逐场播放到失败场**（胜场用 BattleScreen「自动推进」快进、失败场正常播放）→ 之后回到休整；扣一次容错由快照 `failures+1` 生效。
4. 新契约 `autoClimb`，LocalBackend / RemoteBackend / mock-edge / Edge Function 四端同构（同一份 core 规则）。

**胜率预测器 `predictWinRate(team, equipped, formation, layer, strategy, seed)`**（新，确定性）：
- 蒙特卡洛：对该层做 **N=20 次** quick-sim，战斗种子 = `(seed + layer*2654435761 + k*0x9E3779B1) >>> 0`（k=0..19）→ 胜场/20。
- 全部派生自 run.seed → **可复现、双端逐 bit 一致**；不引入任何非确定源。
- 成本：单次 quick-sim ~6ms × 20 ≈ 120ms/层——c2 档位展示与爬塔逐层判定可接受（可后台预计算 + 进度提示）。
- c2 UI：展示「预计胜率 xx%」，可选档位 **51% / 55% / 60% / 65%**（⚠ 开放项 3，档位即阈值，低于不可选）。

### E. c1 战略 buff（爬塔全程生效，用户已确认）

新模块 `applyClimbStrategy(units, strategy, frontRowUids)`（仿 `applyRelics`，支持「前排/全队」分区）：

| 战略 | 前排（靠敌最近一半） | 全队 |
|---|---|---|
| 突袭后排 raidRear | moveSpeed +10（%） | hpMult ×0.92（生命 −8%） |
| 平稳推进 steadyPush | hpMult ×1.15（生命 +15%） | moveSpeed −10（%） |
| 集中突破 breakThrough | — | dmgMult ×1.15（伤害 +15%）、atkSpeed −8（%） |

- 前排定义：布阵后按与敌方出生点的距离排序，取最近 `ceil(人数/2)` 个。⚠ 开放项 2。
- 与天气/relic 同一语义（moveSpeed/atkSpeed 为百分点加减、hp/dmg 为乘区），**进入战斗校验和**，无新随机源。
- 战略选择存快照字段 `climbStrategy`（仅爬塔期间携带，普通战斗不生效）。

### F. 飘字过场（需求 2c 文案）

- 复用现有全局覆盖层：c1/c2 确认后 `setFxBusyWaves('挑战即将开始', '准备迎接梦魇吧！全军突击！')` 或 departScene 风格三秒大字过场 → 期间后台计算 autoClimb → 结果直接呈现（成功=休整汇总；失败=逐场演示）。

## 四、确定性 / 契约影响评估

- ✅ **确定性守卫**：autoClimb / predictWinRate 全部种子派生自 `run.seed`；新增乘区（climbMult/战略 buff/下五层 1.20）都是既有 `enemyScale`/`DerivedAttrs` 的纯乘除，**零 `Math.random`/`sin`/`pow`** → guard 不新增禁令。
- 🔀 **契约增减**：`+autoClimb`、`+advanceLayerTo`、`−skipLayer` → LocalBackend / RemoteBackend / mock-edge / Edge Function **四端同步**；`backend-poc.ts` 的 21 条 PASS 断言不涉及 skipLayer，计数不变。
- 🔀 **受影响测试**：`net-flaky-e2e` / `random-event-e2e` / `reforge-e2e` 迁移到 `advanceLayerTo`；`integration.ts` PRE_ANCHORS 去 `tut-prebattle-skip`。
- ⚠ **快照结构**：新增 `climbStrategy?` 可选字段（前端/快照向后兼容，旧存档无此字段照常）。
- ⚠ **DTO**：`AutoClimbResult` 为新增 DTO，不触碰既有 21 契约字段形状。

1. 「高级奖励概率提升 10%」：默认 = 高奖档（高装+稀装）合计概率 +10 个百分点（0.30→0.40，其余档归一）。
