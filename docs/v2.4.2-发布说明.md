# 无限勇者竞技场 · v2.4.2 发布说明

> **版本体系（v2.0.0 起 · 单一版本基线）**：本版本号 `2.4.2` 与 `package.json`、`CORE_VERSION`、git tag、压缩包名、线上 Pages 共用同一个号。
> 本版本为 **首屏加载修复补丁**：回退 v2.4.0 引入的 `manualChunks` 过度分包，首屏收敛为单包。`packages/core` 引擎**零改动**，确定性逐 bit 一致，回放契约兼容 `2.2.0`（旧 replay / 存档可复用，无需清库或强制刷新）。

## 一、总览

| 维度 | 说明 |
|---|---|
| 版本 | `2.4.2`（2.4 线补丁，首屏加载修复） |
| 核心引擎 | `packages/core` 零改动；parity 逐 bit 一致 |
| 回放契约 | 兼容 `2.2.0`（`CORE_VERSION` 行为不变，冻结 `2.2.0`） |
| 主要目标 | 修复首屏加载过长：回退过度分包，首屏单包 |
| 默认路径 | 100% 不变；进战前由 PreBattle 预载 sim，战斗仍无加载门 |

## 二、问题根因（来自线上反馈"加载中特别长"）

v2.4.0 引入的 `manualChunks` 把 `packages/core` 整包（确定性引擎，~144KB）强制拆成独立 `core` chunk，而首屏 `MainMenu` 因引用 `@arena/core/content/story` 文案，使 `core` chunk 成为首屏**必须加载**的依赖。

线上 `index.html` 首屏要发 **5 个请求**：

| 资源 | 明文大小 |
|---|---|
| main | ~64KB |
| vendor-react（react/react-dom/scheduler） | ~142KB |
| vendor（zustand 等） | ~3.6KB |
| core（packages/core 全量） | ~144KB |
| css | ~31KB |
| **合计** | **~384KB 明文 JS + 31KB CSS，5 次请求** |

GitHub Pages 是静态托管、**不协商 brotli**（vite-plugin-compression2 生成的 `.br` 文件无效，仅自动 gzip 原文件）。5 次请求 + 384KB 明文解析，在冷缓存/慢网下首屏"加载中…"停留明显偏长，且分包带来缓存碎片（任一 hash 变则关联屏缓存失效）。

## 三、变更清单

### ① 回退 manualChunks，首屏单包（vite.config.ts）
- 删除 `rollupOptions.output.manualChunks`（vendor-react / core / vendor 三套分包函数）。
- 首屏收敛为**单包 `main`**（React + 状态管理 + 菜单 UI + 其直接引用的 core 子集一次性就绪）。
- `core` 引擎重型模块（BattleSim 等）随懒加载屏（`BattleScreen` / `IntermissionHub` 等）自然成动态块，**进战前由 `PreBattle` 预载**（`game/battleBuild.ts`），不占首屏请求预算——战斗仍无加载门。
- 保留 `compression` 预压缩（brotli/gzip）与 `input`。

### ② 首屏请求数 5 → 1
| 指标 | v2.4.1（分包） | v2.4.2（单包） |
|---|---|---|
| 首屏 JS 请求 | 4 个（main/vendor-react/vendor/core） | **1 个（main）** |
| 首屏 + css 请求 | 5 | **2**（main + css） |
| 懒加载屏 | 动态块（不变） | 动态块（不变，进战前预载） |
| 缓存碎片 | 多块、易连锁失效 | 单包，命中稳定 |

### ③ core 引擎冻结（parity-safe）
- `packages/core` 零改动，`CORE_VERSION` 保持 `2.2.0`，确定性逐 bit 一致；旧 replay / 存档可复用，无破坏性变更。

## 五、与 v2.4.1 的差异

| 维度 | v2.4.1 | v2.4.2 |

## 六、已知边界
- 本版仅构建配置调整，无 replay / 存档破坏性变更；线上发版按 CICD 手册走全链路 parity 闸门即可。
- 若日后需恢复 vendor 长缓存分包，从 git 历史取回 v2.4.1 的 `vite.config.ts` 的 `manualChunks` 块即可（约 12 行）；但鉴于本版实测首屏更优，不建议回退。
