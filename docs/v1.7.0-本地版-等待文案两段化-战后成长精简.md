> ⚠ **版本体系已统一**：本仓自 **v2.0.0** 起收敛为**单一版本基线** —— `package.json`、`CORE_VERSION`、git tag、压缩包、线上 Pages、全部文档共用唯一版本号 `2.0.0`。本文标题与正文中出现的其它 `vX.Y.Z` 均为**历史里程碑代号**，不再具有发布号效力（详见 `docs/INDEX.md`「版本体系」）。

## 1. 三项需求拆解

### 1.1 1.25s 文字等待动画 → 波两段
所有 1.25s 的 `fxBusy` 遮罩改为「两段波」：先显示 wave1，约 600ms 后切到 wave2，到 1.25s 由调用方原有 `setTimeout` 清掉。
- **战前（PreBattle 倒计时）**：`正在赶往战场` → `准备战斗！`（倒计时由 3 段改为 2 段，总时长 ~1.2s，引擎预载逻辑不变）
- **招募确认（IntermissionHub）**：第一句不变 `恭喜主公新获一员大将` → 第二句 `<角色姓名>誓死追随主公！`
- **其他（招募刷新 / 开箱 / 商店刷新 / 重铸 / 融合 / 升星）**：`正在xx…` → `已完成xx`

### 1.2 战后成长精简
`BattleEval.tsx` 去掉「造成/承受/治疗/移动」明细列与 MVP 数值横幅，改为：
- 主文案：`战后大家都获得了成长`
- 副文案：`具体成长则点开该信息查看。` + 可点击「📊 查看成长详情」展开各勇者累计 `growthBonus`
- 胜负徽章 + 「继续」路由逻辑（按 winner 决定去休整/重试/通关）保留

### 1.3 英雄基础值随机范围大幅增大 + 按基础值定价
- `variateHero` 随机幅度由 ±15%（0.85~1.15）放大到 **±30%（0.7~1.3）**——同角色个体差异显著变大。
- 招募价由纯层数 `60+20*layer` 改为 **按基础值相对预设的偏离浮动**：
  - 四项基础值平均高于预设 **≥10%** → 价格 ×1.10（+10%）
  - 平均高于预设 **≥30%** → 价格 ×2.00（+100%）
  - 平均低于预设 **≤−20%** → 价格 ×0.75（−25%）
  - 其余 → ×1.00
  - 偏离按 `avgDev = mean_k((base_k − preset_k)/preset_k)`，preset 取 `HERO_BY_ID[h.id].basePrimary`（模板预设，非首份副本）。
  - 注：高无用属性也会推高价格，故「贵 ≠ 一定强」，定价只机械反映基础值。
- **关键架构调整（让价格可见且前后端一致）**：招募池在**生成时即个体化**（`variateHero`），`recruit` 直接采用池中英雄（不再二次个体化），价格按池中英雄 `basePrimary` 计算。
  - 受影响生成点：core `startRun` / `refreshRecruit`、前端 `run.ts collectLoot` / `economy.ts refreshRecruit`
  - 受影响招募点：core `recruit`、前端 `economy.ts recruit`
  - UI 招募按钮/可购判定改用每英雄 `recruitCostOf(layer, h.basePrimary, HERO_BY_ID[h.id].basePrimary)`
  - 升星/突破价（HeroPanel）保持 `recruitCost()` 层数定价不变（用户仅要求招募基础值定价）

## 3. 确定性与契约评估
- **确定性守卫**：只禁止 `Math.sin/cos/pow…` 等跨引擎不确定函数。`variateHero` 仍是纯函数 + `mulberry32` 种子驱动，放宽幅度不引入任何 banned 调用 → 守卫保持绿。
- **21 后端契约**：
  - `recruit` 返回的 `Result<RunSnapshot>` 形状不变 → 契约形状不破。
  - 契约 [12] 仅校验 `variateHero` **确定性/差异化**与「同名多份非克隆」，**不锁定具体数值**；池个体化后改为注入个体化池英雄，仍可产出 distinct → 保持绿。
  - 其余契约（DTO 形状、幂等、版本门、校验和）无影响。
- **本地/远程一致**：两种模式均在「生成时个体化池 + recruit 用池英雄」，UI 价与规则扣价同源 → 无漂移。
