> **文档版本**：v1.7　**类型**：子系统设计（装备 / 掉落 / 商店 / 锻造 / 合成 / 升星 / 一次性物品）

## 1. 系统概述

| 模块 | 规则要点 |
|---|---|
| 装备槽 | 每名勇者 **6 个通用槽**（任意装备可装任意槽） |
| 药水 | 每层可使用若干药水（治疗/狂暴/疾速/护盾/净化） |
| 品质 | 普通(common) / 蓝(blue) / 橙(orange) / 红(red) |
| 数量 | 普通 **30** / 蓝 **12** / 橙 **8** / 红 **5**（共 55） |
| 掉落 | 胜利后按关型掉落 **小关 3–6 / Boss 8–12 个箱**（`Chest[]`），每箱按 **40% 普通装 / 20% 少量金 / 20% 高级装 / 10% 稀有装 / 10% 大量金** 产出 |
| 商店 | 每波结束开放；买/卖；交易越多折扣越深 |
| 锻造 | 普通装备每回合 100% 成功随机锻造；可消耗无用普通装提升品质成功率；失败有惩罚 |
| 合成 | 特殊装备不可锻造，仅可合成升阶：蓝 10 / 橙 6 / 红 3，可无限升阶 |

## 2. 词条系统（Affix）

词条即二级属性的增量（见需求 5.3）。通用槽不绑职业，词条为纯数值。

### 2.1 词条池（AffixKey + 普通品质单条随机区间）

| 词条Key | 名称 | 普通区间 |
|---|---|---|
| pDmg | 物理伤害 | 4–9 |
| mDmg | 魔法伤害 | 4–9 |
| hp | 生命 | 25–60 |
| atkSpeed | 攻速% | 3–8 |
| crit | 暴击% | 2–5 |
| critDmg | 暴击伤害% | 6–14 |
| pResist | 物理减伤% | 3–8 |
| mResist | 魔法减伤% | 3–8 |
| moveSpeed | 移速% | 2–6 |
| dodge | 闪避% | 2–6 |
| heal | 治疗量 | 6–16 |

### 2.2 品质倍率（单条值 = 区间 × 倍率，再在倍率内随机）

| 品质 | 倍率 | 词条数 |
|---|---|---|
| 普通 | ×1.0 | 1 |
| 蓝 | ×1.8 | 2 |
| 橙 | ×3.0 | 2–3 |
| 红 | ×5.0 | 3 |

> 设计目的：满足「设计一堆高低随机值的词条」——同一词条在不同装备/锻造下呈现高低差异。

## 3. 装备品质与被动

- **普通/蓝**：纯词条（蓝为双词条）。
- **橙**：2–3 词条 + **1 个被动**（职业向）。
- **红**：3 词条 + **1 个强化被动**（职业向，更强）。
- **被动**为职业专属机制，需战斗引擎加 `unit.passives` 钩子（见 §10）。

## 9. 掉落系统（v1.7 重写）

- 触发：每一波/层胜利后，进入休整界面前的 `collectLoot(layer)`。
- **箱数按关型**：
  - **普通小关**：`chestCount(layer,false)` = **3–6 个**（`randInt(3,6)`）。
  - **Boss 关**（每 5 层）：`chestCount(layer,true)` = **8–12 个**（`randInt(8,12)`）。
- 数据结构：`pendingDrops: Chest[]`，每个 `Chest` 由 `rollChestReward(rng, isBoss)` 决定 `kind` 与内容，开箱（`openDrop`）才落地到背包或金币：

| 箱类型 `kind` | 权重 | 内容 |
|---|---|---|
| `equip_common` 普通装备 | **40%** | 1 件普通（common）装备 |
| `gold_small` 少量金钱 | **20%** | `goldReward(layer) × randInt(1,2)`（约 1–2 层基准金） |
| `equip_advanced` 高级装备 | **20%** | 1 件蓝/橙（blue/orange）装备 |
| `equip_rare` 稀有装备 | **10%** | 1 件红（red）装备 |
| `gold_big` 大量金钱 | **10%** | `goldReward(layer) × randInt(4,7)`（约 4–7 层基准金） |

- 实现入口：`equipment.ts` 的 `chestCount()` / `rollChestReward()` / `rollDrops()`；
  `store.ts` 的 `collectLoot()` 写入 `pendingDrops`，`openDrop(id)` 按 `kind` 分发。
- 深层（大师赛后）可略微提升高品质装备权重——**不改变总箱数**，只调整 `equip_*` 内部品质。

## 10. 与战斗引擎集成（被动钩子）

`Unit` 增加 `passives: string[]`。各被动在引擎中的触发点：

| 被动 | 引擎钩子位置 |
|---|---|
| 处决 | `applyDamage` 中：若 `crit && target.hp/target.maxHp < 斩杀线` → `target.hp=0` |
| 吸血 / 汲取 | `dealSkill`/`basicAttack` 结算后：`source.hp += dmg × 比例`（不超过 maxHp） |
| 再生 | 每波开始：`u.hp = min(maxHp, hp + maxHp×0.05)` |
| 连锁 | `castSkill` 对主目标后：对 2 格内敌人追加 30% 伤害 |
| 冷却缩减 | 创建单位时：`skill.cd ×= 0.8`（强化 ×0.65） |
| 反伤 | `applyDamage` 中：若 `target.shield>0` 且含反伤 → 来源受 `dmg×0.15` |
| 不朽 | `applyDamage` 中：若 `hp<=0 && undyingCharges>0` → `hp=1; undyingCharges--` |
| 奥能过载 | `dealSkill` 技能伤害 `×1.3` |

## 11. 商店系统（v1.4 重构：三货架）

### 11.1 三货架结构

每层结束开放商店屏，分**三条独立货架**，各自服务一个不同的资源转化决策。分开陈列而不是混在一个列表里，是因为它们的决策周期完全不同：装备是"现在变强"，消耗品是"下一层保险"，英雄是"整局的构筑方向"。

| 货架 | 库存量 | 内容 | 刷新 | 玩家在问自己什么 |
|---|---|---|---|---|
| **装备架** | 4–6 件 | 按权重生成（多数普通，少量蓝/橙，红极稀有）；含 **1–2 件预打折商品**（10–20% off） | 每层 | 「这件能不能立刻提升我的输出/生存」 |
| **消耗品架** | 3–4 种 × 各 0–3 个 | 药水 §8 五类 + **稳固药剂（v1.4 新增，锻造保护料）** | 每层 | 「下一层的方差我要不要买保险」 |
| **英雄架** | 2–3 名 | 随机勇者，**包含队伍已拥有的重复角色**（用于升星，§11.5） | 每层 | 「铺人数还是升星」 |

**英雄架的刷新权重**（`rollRecruitPool`）：

```
候选池 = 全部勇者
权重规则：
  · 队伍尚未拥有的子类        权重 3.0    ← 保证阵容多样性优先
  · 队伍已拥有、但星级 < 5    权重 2.0    ← 升星料，v1.4 新增
  · 队伍已拥有、且星级 = 5    权重 0      ← 满星角色不再出现，不浪费格子
  · 队伍已满 7 人时，未拥有子类权重降至 1.0，已拥有升 3.0   ← 满编后转向升星
```

> 满编后自动把权重倒过来，是因为**玩家的需求在满编那一刻整个换了**。7 人满了还刷一堆新角色，等于三个格子里有两个是废的。这条规则不是平衡，是尊重玩家的时间。

### 11.2 折扣曲线（交易越多越深）
```
tradeCount = 累计买入 + 卖出 次数
discount   = clamp(tradeCount × 0.025, 0, 0.5)   // 满 20 次交易封顶 50% off
buyPrice   = basePrice × (1 − discount)
sellPrice  = basePrice × 0.5 × (1 − discount × 0.5)   // 卖出折扣影响更小
```
> 设计意图：把「逛店」变成正反馈循环——越交易越便宜，鼓励经济深度（需求 5.7 经济熔断的反面：这里用折扣而非通胀）。
>
> **v1.4 例外**：折扣曲线**只作用于装备架和消耗品架，不作用于英雄架**。理由——英雄价格是本作的主力抗通胀 sink（需求 §5.8），如果它也跟着打 5 折，深层玩家会用白菜价把满编 5 星凑齐，这个坑就填平了。折扣的意义是奖励"频繁交易的经营型玩家"，而不是"给所有东西打折"。

**消耗品架**
| 消耗品 | 价格 | 作用 |
|---|---|---|
| 小治疗药水 | 40 | 恢复 30% HP |
| 大治疗药水 | 90 | 恢复 70% HP |
| 力量药剂 | 60 | 本层 +20% 物理伤害 |
| 迅捷药剂 | 60 | 本层 +15% 攻速 |
| 护体药剂 | 70 | 本层 +15% 全减伤 |
| **稳固药剂**（v1.4） | **80** | 锻造时消耗，失败不触发惩罚（仅本次无效果），见 §12.4 |

> 稳固药剂定价 80 = 一件普通装（30）的 2.7 倍，也 ≈ 一次高投入锻造的 gold 成本。**它的价格必须让"买保险"是一个要犹豫的决策**：便宜到随手买，锻造的风险就消失了；贵到没人买，它就是个摆设。80 是我推的落点。`[PLACEHOLDER · 验证路径：埋点统计锻造时稳固药剂的使用率，目标区间 25%–45%；<20% 说明太贵，>60% 说明太便宜]`

### 11.4 英雄架定价（v1.4 新增）

```
heroPrice = 120 + 40 × (当前队伍人数 − 3) + 60 × (该英雄当前星级 − 1)
```

价格实例（便于直观校验）：

| 场景 | 计算 | 价格 |
|---|---|---|
| 开局 3 人，招第 4 人（1 星） | 120 + 40×0 + 60×0 | **120** |
| 已 5 人，招第 6 人（1 星） | 120 + 40×2 + 60×0 | **200** |
| 已 7 人满编，买 1 星角色升星 | 120 + 40×4 + 60×0 | **280** |
| 已 7 人满编，买同名 3 星角色 | 120 + 40×4 + 60×2 | **400** |
| 已 7 人满编，买同名 4 星角色 | 120 + 40×4 + 60×3 | **460** |

单角色从 1 星凑到 5 星的**累计成本**（满编状态下）：`280 + 340 + 400 + 460 = 1480 gold`，≈ 1.2 件红装。7 人全部 5 星理论需 **约 10360 gold** —— 这是一个玩家一辈子填不满的坑，正是无尽模式需要的 sink 形态。

### 11.5 升星系统（v1.4 新增 · 需求 §5.7.3）

| 项 | 规格 |
|---|---|
| 触发 | 编队界面拖拽同 `heroId` 的一名英雄到另一名身上 → 确认框（**必须展示合并后完整属性预览**）→ 合并 |
| 消耗 | 被拖走者消失，**其装备自动退回背包（不销毁）** |
| 上限 | 5 星 |
| 属性 | 一级属性 × `(1 + 0.18 × (star − 1))` |
| 成长 | `growth + 1 / 星`（2 → 6） |
| 可逆 | **不可逆** |

| 星级 | 属性倍率 | growth | 相当于 |
|---|---|---|---|
| 1★ | 1.00× | 2 | 基准 |
| 2★ | 1.18× | 3 | ≈ 一件橙装 |
| 3★ | 1.36× | 4 | ≈ 两件橙装 |
| 4★ | 1.54× | 5 | — |
| 5★ | **1.72×** | **6** | ≈ 三件橙装的全属性版本 |

> **growth 那一列才是重点。** 属性倍率 1.72× 在 10 层内很香，30 层后层数成长项主导，只加基础值的升星会贬值成鸡肋。growth 从 2 → 6（3 倍）保证高星角色在深层持续拉开差距。设计上我宁可把 0.18 调低也要保住 growth +1/星。
>
> `[PLACEHOLDER · 0.18 与 growth +1]` **验证路径**：500 次 30 层 Monte Carlo，对比「3人×5星」「5人×3星」「7人×1星」三条极端路线的到达层数分布。目标是三条曲线在 25–35 层交叉，即**没有支配解**。若 3×5星 明显领先则 0.18 → 0.12；若 7×1星 领先则 growth → +1.5/星。

**同名多份上场**：允许，不强制合并。视觉区分见美术 §4.6（罗马数字后缀 + 臂章像素 + 头顶星级）。「升星 vs 铺人数」是本作最主要的构筑决策，**不给最优解**，靠站位上限（前排≤3 / 中排≤2 / 后排≤2）自然收敛——铺人数路线会先撞排位天花板，被迫转向升星。结构性约束比数值调平更稳。

### 11.6 装备架一次性物品（v1.7 §4 · 新需求）

v1.7 起，**装备架每个货位独立以 20% 概率（`CONSUMABLE_CHANCE=0.2`）翻转为一次性物品**，而非固定数量的药水货架。8 个货位中约 1.6 个会是一次性物品（逐位判定，玩家无法背板库存结构）。一次性物品通过 `consumables` 货架展示，购买后进入 `consumables` 背包，在休整界面对指定副本使用，**用后即从背包移除**（一次性）。

两种一次性物品（实现见 `src/game/content/consumables.ts`）：

| 物品 | 效果 | 作用域 | 生效方式 |
|---|---|---|---|
| **成长药剂（Growth Potion）** | 随机 1 项**核心属性 +0.5**（con/str/agi/int 任选）、随机 1 项**二级属性成长 0.5%~2%**（hp/pDmg/mDmg/heal 任选，百分点累加） | 永久 | 立即写入该副本 `growthBonus`，下场战斗通过 `makeAlly` 的 `applyGrowthPct` 结算 |
| **爆发药剂（Burst Potion）** | 主属性（`dominantPrimary`）增强 **+50%**，持续 **1 回合** | 下一场战斗 | 标记副本 `pendingBurst=true`；进入战斗时 `consumeBurst(uid)` 触发，`makeAlly` 把 `+50%` 主属性叠到 `primary` 并伴随 `burst` 视觉辉光；战斗结束清空标记 |

- 成长药剂让「买药」成为一条**永久养成线**，与装备/升星并列；爆发药剂是「下一层搏一把」的**方差保险**，1 回合短窗口避免长期滚雪球。
- 商店总货位数恒为 **8**（`rollShopStock(rng,8)`：8 个货位 = 装备数 + 一次性物品数），故「装备数量」不再恒为 8。

## 12. 锻造工坊（v1.4 重构）

### 12.0 v1.3 版本的四个病灶（先说清楚在修什么）

| # | 病灶 | 症状 | v1.4 修法 |
|---|---|---|---|
| 1 | **无成功率预览** | 玩家滑动选择消耗 N 件，但直到点确认都不知道概率是多少。等于蒙眼下注 | §12.2 实时预览条 |
| 2 | **只能锻普通装** | 20 层后普通装备全被淘汰，整个锻造系统在中后期死亡 | §12.3 开放蓝装锻造 |
| 3 | **失败惩罚不可读** | 静默改数值，玩家只看到装备变弱了但不知道发生了什么 | §12.5 明确文案 + 高亮 |
| 4 | **每层限 1 次太慢** | 7 人满编 × 6 槽 = 42 件装备，每层锻 1 次意味着一件装备平均 42 层才轮得到 | §12.6 改为每层 3 次共享池 |

外加一个经济问题：v1.3 锻造**不消耗金币**，只吃废装。废装是本来就要卖掉的垃圾，等于免费彩票——没有机会成本就没有决策感。v1.4 追加 gold 成本（§12.4）。

### 12.1 核心规则

- **100% 重 roll**：锻造必定重 roll 词条；「成功率」指**品质成功率**（是否出高值区 / 是否触发惩罚），不是"会不会有反应"。
- 可**消耗无用装备**（N 件，同品质）提升成功率。
- **每层全队共享 3 次**锻造次数（§12.6）。
- 橙/红装**不可锻造**，只能合成（§13）。

### 12.2 成功率公式与实时预览（硬要求）

```
普通装：successRate = clamp(0.45 + N × 0.11, 0, 0.95)     // 保持 v1.3 不变
蓝  装：successRate = clamp(0.30 + N × 0.08, 0, 0.85)     // v1.4 新增

if roll < successRate:
    重roll 全部词条，取值 = 区间 × 倍率 × [0.7, 1.0]      // 高值区
else:
    惩罚（随机其一，见 §12.5）
```

**蓝装三重削弱的 rationale**：基线 0.30（比普通低 15pt）、每件燃料 +0.08（比普通低 0.03）、天花板 0.85（比普通低 10pt）。三项一起削，是要让「锻蓝装」成为一个**有意识的高风险投入**，而不是"普通装的平替玩法"。橙/红继续锁死，保住顶级装备作为稀缺锚点——一旦顶级装备可以刷，整条装备价值链就塌了。

**成功率预览条（UI 硬要求，不可裁剪）**：

| 元素 | 规格 |
|---|---|
| 燃料滑条 | 拖动选择 N（0 → 背包中同品质废装数量上限） |
| 成功率数字 | **实时**显示 `successRate` 百分比，字号 ≥ 18px，颜色按档位：<50% 红 / 50–75% 黄 / >75% 绿 |
| 期望词条区间 | 显示成功时的词条值范围（如 `pDmg 9–13`），让玩家判断"值不值得赌" |
| gold 成本 | 实时显示 `forgeCost`（§12.4），与成功率同屏 |
| 确认按钮 | gold 不足时置灰，**不允许在不知道概率的情况下点确认** |

> 这条是红线：**任何要求玩家承担随机风险的系统，都必须在决策点之前给出概率**。藏概率不叫增加刺激，叫欺骗——玩家早晚会自己算出来，然后不再信任你的每一个数字。

### 12.3 可锻品质范围

| 品质 | 可锻 | 基线成功率 | 每件燃料 | 上限 | 燃料要求 |
|---|---|---|---|---|---|
| 普通 | ✅ | 0.45 | +0.11 | 0.95 | 消耗普通装 |
| 蓝 | ✅（v1.4 开放） | 0.30 | +0.08 | 0.85 | **必须消耗蓝装**（不能拿普通装喂蓝装） |
| 橙 | ❌ | — | — | — | 走合成 §13 |
| 红 | ❌ | — | — | — | 走合成 §13 |

> 「蓝装只能吃蓝装」这条约束很关键。若允许普通装喂蓝装，玩家会把每层捡到的十几件白装全塞进去，蓝装锻造瞬间变成 85% 稳出——三重削弱白设计了。**燃料必须同级**，这样锻蓝装的机会成本就是"少一件能穿的蓝装"，真实且疼。

### 12.4 金币成本（v1.4 新增）

```
forgeCost = 20 + 15 × N + (品质 == 蓝 ? 60 : 0)
```

| 场景 | 计算 | 成本 |
|---|---|---|
| 普通装，不喂料（45%） | 20 + 0 | **20** |
| 普通装，喂 3 件（78%） | 20 + 45 | **65** |
| 普通装，喂 5 件（95% 封顶） | 20 + 75 | **95** |
| 蓝装，喂 3 件（54%） | 20 + 45 + 60 | **125** |
| 蓝装，喂 7 件（85% 封顶） | 20 + 105 + 60 | **185** |

**rationale**：
- 基础 20 = 一件普通装售价的 2/3。低到不会阻止玩家尝试，但足以让"每层无脑锻三次"变成一笔要算的账。
- 每件燃料 +15 而不是固定总价：**让"堆成功率"这个行为本身也变贵**，成功率曲线和成本曲线同步上扬，保证高成功率始终是一个投入决策。
- 蓝装 +60 固定附加费：与蓝装 basePrice 120 的一半对齐——锻一次蓝装的手续费 = 半件蓝装。

> `[PLACEHOLDER · 基础 20 / 每件 15 / 蓝装 +60]` **假设**：20 层累计 gold 收入 1800–2400，锻造应吃掉其中 10–18%。**验证路径**：埋点统计单局锻造总花费占 gold 总收入比例；若 < 8% 说明太便宜（锻造没有机会成本），若 > 25% 说明挤压了装备架和英雄架的预算，要降。

### 12.5 失败惩罚（可读化）

失败时随机触发其一，**必须弹出明确文案**，不允许静默改数值：

| 惩罚 | 文案模板 | 数值 |
|---|---|---|
| 削弱 | `锻造失败：〈{词条名}〉降低 30%（{旧值} → {新值}）` | 1 条词条 ×0.7 |
| 移除 | `锻造失败：〈{词条名}〉在高温中崩解` | 移除 1 条词条 |
| 弱化替换 | `锻造失败：〈{旧词条}〉扭曲为〈{新词条}〉` | 替换为更弱词条 |
| 附加负词条 | `锻造失败：附着了〈{负词条名} {效果}〉` | 加 1 条负面词条 |

**负面词条表**
| 负面 | 效果 |
|---|---|
| 锈蚀 | pDmg −3 |
| 脆弱 | hp −15 |
| 迟缓 | atkSpeed −3% |
| 麻木 | crit −2% |

**UI 要求**：结果弹窗中受影响的词条行**高亮红色 + 显示旧值划掉→新值**，持续到玩家手动关闭。玩家必须能一眼看懂"我失去了什么"。默默变弱是最伤信任的做法——玩家不会以为自己运气差，只会以为游戏在偷数值。

### 12.6 稳固药剂（保护料 · v1.4 新增）

- 锻造时可**额外消耗 1 瓶稳固药剂**（消耗品架，80 gold，§11.3）。
- 效果：失败时**不触发四选一惩罚**，改为「本次锻造无效果」（词条不变，燃料和 gold 照常消耗）。
- UI：预览面板上一个独立勾选框，勾上后成功率数字旁显示盾牌图标 + 文案「失败时不会变弱」。

> 这是所有强化系统的标配 sink，作用是**给玩家一个把方差换成金币的选项**。它不改期望值（燃料和 gold 照扣），只削掉左尾——正好服务那些"这件装备我很在意，不敢赌"的时刻。没有这个选项的强化系统，玩家的策略只有"用垃圾装备赌"，好装备永远不敢碰，等于系统只覆盖了一半的物品。

### 12.7 次数池与 UI 合并

| 项 | v1.3 | v1.4 |
|---|---|---|
| 次数 | 每件装备每层 1 次（`forgeThisLayer` 标志挂在装备上） | **每层全队共享 3 次**（`forgeChargesLeft` 挂在 store 上） |
| UI | 锻造与合成分离在两处 | **合并为「锻造工坊」单一界面，两个 Tab：`锻造` / `合成`** |

**为什么从"每件 1 次"改成"全队 3 次"**：7 人满编 × 6 槽 = 最多 42 件在用装备，加背包库存可能上百件。每件每层限 1 次听起来是限制，实际上等于**没有限制**（玩家永远有没锻过的装备），真正的瓶颈是燃料。改成全队 3 次之后，限制才真正生效——玩家每层必须选"这 3 次给谁用"，这是一个真决策。

> 3 次的选取理由：层间休整的心理预算大约是 30–60 秒，3 次锻造（含预览思考）刚好填满而不拖沓。`[PLACEHOLDER · 3 次]` **验证路径**：埋点统计层间停留时长，若中位数 > 90 秒说明层间太重、节奏被打断，降到 2 次。

## 13. 合成系统（特殊装备升阶）

> **v1.6 修订**：原 10/6/3 件的高门槛在实测中几乎不可达（玩家极少同时持有 10 件同色），合成系统形同虚设。v1.6 改为 **两件低阶合一件高阶** 的短周期路径，并把「无限升阶」收敛为 **红装五星封顶**，让成长曲线有明确终点。

### 13.1 跨品质合成（Fuse）

| 素材 | 产物 |
|---|---|
| **2 件蓝装** | 1 件**随机橙装**（重新生成部位与词条） |
| **2 件橙装** | 1 件**随机红装**（重新生成部位与词条） |

- 产物等级取两件素材中的较高者。
- 素材一律销毁；合成不消耗金币，但**每层限 2 次**（`fusedThisLayer`），防止无限刷。

### 13.2 红装升星（Ascend）

- **红装 + 任意红装 → 目标红装 star + 1**，素材销毁。
- 星级范围 **1★ ~ 5★**，5 星为硬上限，已满星装备不可再作升星目标。
- 星级效果：**所有词条数值 × (1 + 0.25 × (star − 1))**
  → 1★ = 1.00× / 2★ = 1.25× / 3★ = 1.50× / 4★ = 1.75× / **5★ = 2.00×**。
- 装备名前缀显示星数，如 `★★★ 炽炎战铠`。

### 13.3 与锻造的关系

合成/升星走的是**品质线**，锻造转移（开发文档附录 A.4）走的是**词条线**，两条线互不冲突：
一件 5★ 红装仍可作为锻造转移的目标，继续吸收素材词条 —— 这构成 v1.6 的终局装备养成闭环。

## 14. 经济平衡建议（gold 源/汇）

| 类型 | 项 | 量级特征 | v1.4 状态 |
|---|---|---|---|
| **源** | 每层胜利奖励 gold | 随层数**线性增长** | 不变 |
| **源** | 卖装备（半价回收） | 随掉落量增长 | 不变 |
| **源** | 事件 gold / 赛季里程碑 | 一次性 | 不变 |
| **汇** | 装备架购买 | 固定四档常数 30/120/400/1200 | ⚠️ **不随层数涨，深层吃不下产出** |
| **汇** | 消耗品架 | 40–90/瓶，每层稳定消耗 | 稳定但量小 |
| **汇** | 合成手续费 | 随 tier 递增 | 抗通胀 ✅ |
| **汇** | **英雄架（v1.4）** | 120 → 460/次，随**人数 × 星级**双重递增 | ✅ **主力抗通胀 sink** |
| **汇** | **锻造 gold 成本（v1.4）** | 20–185/次 × 每层 3 次 | ✅ 随投入递增 |
| **汇** | **稳固药剂（v1.4）** | 80/瓶，方差换金币 | ✅ 高价值物品专用 sink |

**v1.4 修的是哪个洞**：v1.3 的所有 sink 都是**定价常数**，而 source 随层数线性增长。数学上必然在某层交叉——过了那一层，gold 就变成无意义的数字，商店失去张力。三个新 sink 里，**英雄架是主力**：它的价格随「队伍人数 × 星级」双重递增，恰好在玩家最有钱的深层胃口最大。单角色 1★→5★ 累计 1480 gold，7 人全 5 星约 10360 gold —— 一个填不满的坑，正是无尽模式需要的形态。

> `[PLACEHOLDER · source/sink 交叉点]` **验证路径**：Monte Carlo 跑 50 层，逐层记录「gold 余额」曲线。**健康的曲线应在 15–35 层保持在 0–500 区间震荡**（玩家总是差一点钱），而不是单调爬升。若 30 层后余额突破 2000 且持续上升，说明 sink 还是不够，下一刀砍在装备架定价上——把四档常数改成 `basePrice × (1 + 0.03 × depth)`。
