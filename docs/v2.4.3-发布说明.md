# 无限勇者竞技场 v2.4.3 发布说明

> 发布日期：2026-08-15 ｜ 类型：体验修复（前端过场加载门） ｜ CORE_VERSION 冻结 2.2.0（parity-safe）

## 问题

出征 / 开战两段过场动画（弹字动画）播完后，屏切换会触发 `React.lazy` 懒加载 chunk 下载，期间
Suspense 兜底「加载中…」直接裸露，造成可见的加载停顿——违背了「动画一开始就把后端发送 / 资源预载并行做了，不该有载入中」的设计意图。

## 根因

开战倒计时（`PreBattle.confirm` 两段过场）结束 `screen` 翻到 `battle` 时，`BattleScreen` 是
`React.lazy` 组件 chunk；倒计时遮罩在 `countdown→0` 移除后、chunk 下载完成前，Suspense 兜底
「加载中…正在准备战场」裸露。此前代码只预载了 sim 引擎（本地）与云端 `startBattle`，**漏了预载
`BattleScreen` 组件 chunk 本身**，加载门仍在。

## 修复

两处纯并行 `import()` 预载（不改变任何既有逻辑、不影响确定性契约、core 零改动）：

| 文件 | 位置 | 改动 |
| --- | --- | --- |
| `src/screens/PreBattle.tsx` | `confirm()` 开头 | 倒计时开始即 `void import('./BattleScreen')`，与 sim 预载 / 云端 `startBattle` 并行 → 动画结束 chunk 已缓存，`React.lazy` 直读缓存，无 Suspense 兜底 |
| `src/screens/TeamBuilder.tsx` | `depart()` 出征台词开始 | `void import('./PreBattle')`，与 `startRun` 并行（兜底防覆盖层透出「加载中」） |

预载 specifier 与 `App.tsx:10-11` 的 `React.lazy(() => import('./screens/PreBattle'|'./screens/BattleScreen'))`
解析到同一模块 → 命中同一 chunk，不生成重复包。
