## 0. 结论先行

前六份文档的承重假设是：

> 战斗引擎是确定性的，所以后端只下发 `seed + 快照`，**前端本地跑同一份引擎复现**。

**这个假设一开始不成立，现在成立了。** 过程分三步：

| 阶段 | 认知 | 依据 |
|---|---|---|
| 初版 | "确定性 OK"——不用 `Math.random`/`Date.now` 就够了 | 只在 **Node 单运行时**跑了 79 场，全等 |
| 第一次翻车 | 跨**浏览器厂商**会漂（Chrome / Firefox / Safari 第 18 场分叉 621/607/651 tick） | `floatscan` 2 万点扫描 |
| **第二次翻车** | 跨**同一引擎的大版本**也会漂（V8 12.4 vs V8 15.0，六个函数全不同） | 本文 §2 表 |

第二次翻车比第一次严重得多。第一次的风险还能靠"给 Safari 用户降级"绕过；
第二次意味着 **Supabase 例行升级一次 Edge Runtime，全体玩家的本地回放就会静默对不上**——
没有任何报警会响，因为服务端自己算得好好的。

修复方式：把演算路径上的超越函数全部换成自实现的确定性版本（`src/game/engine/detmath.ts`），
并加一道静态闸门防止回潮。

## 1. 根因：ECMA-262 把 `Math` 分成了两档

| 档位 | 成员 | 规范措辞 | 跨实现 |
|---|---|---|---|
| 强制 | `+ − × ÷`、`Math.sqrt`、`round`/`floor`/`ceil`/`abs`/`min`/`max` | 遵循 IEEE 754-2019，**必须正确舍入** | **逐 bit 一致** |
| 近似 | `sin cos tan asin acos atan atan2 hypot exp log pow cbrt` 等 | *"implementation-approximated"* | **允许各不相同** |

第二档的规范原文只要求"使用被广泛接受的近似算法"，**没有任何 ULP 约束**。
也就是说：这不是某个浏览器的 bug，而是规范明确许可的行为。指望"以后会统一"不现实。

`**` 运算符在规范里等价于 `Math.pow`，同属第二档 —— 这一点很容易漏。

## 2. 实测证据：五个运行时，2 万点/函数的 bit 级摘要

对每个函数喂同一批 20000 个确定性输入（`mulberry32(20260808)`），
把全部结果串起来压成摘要比对：

| `Math.log` | `6c4ced60` | `-2154eb66` | `6c4ced60` | `-2154eb66` | 2 |
| `Math.sqrt` | `-783552c1` | `-783552c1` | `-783552c1` | `-783552c1` | **1** ✅ |

三个要点：

1. **`Math.sqrt` 是唯一全场一致的** —— 与规范预测完全吻合，第一档就是第一档。
2. **`Math.sin`/`cos` 有 4 种实现** —— 4 个运行时给出 4 个不同答案。
3. **V8 12.4 与 V8 15.0 在 6 个函数上不同** —— 同一个引擎，隔三个大版本。
   这条最容易被忽略，也最危险：它把"浏览器兼容性问题"升级成了"部署环境漂移问题"。

### 为什么手挑探针会骗过你

第一版 `selfcheck` 手挑了 7 个探针值（`Math.hypot(3.7, 8.3)`、`Math.cos(0.6154797086703873)` …），
在三个浏览器上**全部 PASS**，据此差点得出"Firefox 没问题"的错误结论。
换成 2 万点采样后，同样这三个引擎立刻分道扬镳。

> **教训：验证浮点一致性必须做大规模扫描。抽查几个"看起来有代表性"的值等于没查。**
> 现在 `selfcheck.html` 的对照组用的就是和实验组完全相同的 2 万点输入。

## 3. 影响面：核心演算路径，不是渲染

改造前，headless 三层（`engine` / `content` / `gen`）里的调用点：

| 位置 | 用途 | 是否进校验和 |
|---|---|---|
| `battle/common.ts` `dist()` | 移动、索敌、分离推挤 | ✅ 是（被全引擎调用） |
| `battle.ts` × 13 处 `Math.hypot` | 弹道落点、范围判定 | ✅ 是 |
| `battle.ts:1669` `Math.cos(35°)` | 龙息**锥形 AoE 的张角判定** | ✅ 是 |
| `battle.ts:1141` `cos/sin` | Boss 分身**出生坐标** | ✅ 是 |
| `battle.ts:1943` `cos/sin` | 建筑守卫**铺位坐标** | ✅ 是 |
| `scaling.ts:35` `Math.pow(n/k, 0.5)` | **敌人 HP / 伤害缩放** | ✅ 是（后期才发现） |
| `arenas.ts:255` `Math.pow(0.9, cycle)` | 主题褪色 → `Math.round` 到 0–255 | 颜色取整边界 |
| `battle.ts:260` / `1693` | 特效环形阵列、光束朝向 | ❌ 纯渲染 |

`scaling.ts` 那处是**第二轮排查才揪出来的**——第一轮只盯着三角函数，
完全没想到 `Math.pow` 也在名单上，而它直接决定每一层敌人的血量。
这也是后来加静态闸门的直接原因：靠人眼逐个找，一定会漏。

## 4. 修复：`detmath.ts` + 静态闸门

### 4.1 确定性数学库

`src/game/engine/detmath.ts`，只用第一档运算重写：

| 导出 | 实现要点 |
|---|---|
| `dsin` / `dcos` | Cody-Waite 幅角规约 + fdlibm kernel 多项式 |
| `dpow` | 快路（`0/1/2/±0.5/整数`）+ 通用路 `e^(y·ln x)` |
| `dpowi` | 整数次幂，平方求幂 |
| `drot` | 向量旋转 —— 用来**替代 `atan2`**（见下） |

**它不追求"和 `Math.*` 结果相同"，只追求"处处相同"。** 与 V8 的偏差在 1 ULP 量级。

两个实现细节值得记下来，都是踩出来的：

- **幅角规约的 `π/2` 必须低位清零。** 直接用"离 π/2 最近的 double"，
  `k * PIO2_HI` 这一步本身就会舍入（k=25 时误差 3.6e-15），
  实测把 `|x|≤40` 区间的 sin 误差顶到 3.6e-15、超出验收线。
  改用 fdlibm 的 `pio2_1`（低 33 位为 0）后乘法精确，误差降到 1e-16 量级。
- **`dpow` 对 `y === 0.5` 走 `Math.sqrt` 快路。** 这不只是性能：
  `enemyScale` 的默认指数就是 0.5，走精确快路意味着**改造前后数值平衡逐 bit 相同**，
  不需要重新调平衡。

验收：`test/detmath.test.ts` 9 项，sin/cos 在 ±40 rad 上误差 < 1e-15，
`dpow(n/20, 0.5)` 对 n=21..500 与 `Math.pow` **完全相等**。

### 4.2 消掉 `atan2`：不求角，直接转向量

`detmath` 里**没有** `atan2` —— 因为压根不需要。原代码的模式是
"求出朝向角 → 加偏移 → 用 cos/sin 还原成向量"，中间那个角是多余的：

```ts
// ❌ 三次超越函数调用，且 atan2 跨引擎不确定
const base = Math.atan2(ay, ax);
const a = base + i * 14 * Math.PI / 180;
const tx = u.x + Math.cos(a) * range, ty = u.y + Math.sin(a) * range;

// ✅ (ax, ay) 本来就是单位向量，直接旋转它
const d = drot(ax, ay, i * 14 * DEG);
const tx = u.x + d.x * range, ty = u.y + d.y * range;
```

同理，**锥形 AoE 判定**不需要求角，点积就够（原代码已是点积法，
只是那个 `Math.cos(35°)` 阈值常量本身不确定，换成 `dcos(35 * DEG)` 即可）。

### 4.3 静态闸门

`scripts/guard-determinism.mjs`，已并入 `npm run verify` 第三道：

```
✓ 确定性闸门：src/game/engine / src/game/content / src/game/gen / src/backend 全部干净
```

- 扫描四个 headless 层，命中第二档 `Math.*` 或 `**` 运算符即 **exit 1**
- 渲染层（`src/render`、`src/ui`）不管 —— 那里的抖动只影响像素
- 例外写 `det-ok` 注释（同行或紧贴的注释块），并说明理由。当前仅两处：
  - `detmath.ts` 里 `Math.pow` 处理 `±Infinity/NaN`（规范逐条穷举定死，无自由度）
  - `LocalBackend` 生成 run 根种子的 `Math.random`（**要的就是不确定性**）

写这个闸门时自己也踩了个坑：仓库是 CRLF 换行，而 JS 正则里 `\r` 属于行终止符、
`.` 不匹配它，导致 `/\/\/.*$/` 的 `$` 锚点永远失败、**整行注释一个字都剥不掉**，
中文注释里的 Markdown `**加粗**` 全被当成幂运算符报了上来（20 条假警报）。
一个会刷屏假警报的闸门必然会被关掉，所以工具本身也要验——
现在有注入违规文件、确认 exit 1 再删除的自检流程。

## 5. 验证结果（五运行时）

| 运行时 | 引擎 | 战斗指纹 | tick 序列 | 本地复现 vs 后端 | detmath 摘要 |
|---|---|---|---|---|---|
| Node 22.13 | V8 12.4 | `-122f581e` | 一致 | 全等 | ✅ |
| Deno 2.9.5 | V8 15.0 | `-122f581e` | 一致 | 全等 | ✅ |
| Chromium 151 | V8 15.0 | `-122f581e` | 一致 | 全等 | ✅ |
| Firefox 153 | SpiderMonkey | `-122f581e` | 一致 | 全等 | ✅ |
| WebKit 26.5 | JavaScriptCore | `-122f581e` | 一致 | 全等 | ✅ |

18 场基准战斗（3 seed × 逐层推进，含一场 1292 tick 的长局），
**36 个 checksum（18 权威 + 18 本地复现）在五个运行时上逐 bit 全等**。
此前分叉的第 18 场，现在五处统一为 621 tick / `1fdc6b4ec24b6e`。

同一份页面的对照组同时显示：这些引擎的原生 `Math.sin/cos` 依然是 4 种不同实现。
**"全绿"本身没有信息量，对照组飘红才证明修复真的生效了。**

### 性能代价：0.01%

| 指标 | 实测 |
|---|---|
| detmath 调用频次 | 1335 次 / 33 场 = **40 次/场** |
| 单次成本 | `dsin`/`dcos` 38.3 ns（原生 11.1 ns，慢 3.4×） |
| 折算总耗时 | 0.051 ms / 500 ms = **0.01%** |

慢 3.4× 听起来不少，但调用点全在 Boss 分裂 / 守卫铺位 / 龙息锥形这类**低频事件**上，
不在 per-tick 热路径。战斗耗时随 tick 数近似线性：
新手短局（~70 tick）3.3 ms/场，无尽深层（~307 tick）15.2 ms/场。

## 6. 对架构的影响

**核心架构不用推翻，而且现在比原来更硬。**

`startBattle` 的响应同时包含：

```ts
replay:  { battleSeed, allies, enemies, arena, buildings, checksum }  // 回放输入
outcome: { result, totalTicks, stats, ... }                          // 权威结果
```

**胜负、掉落、成长一律以 `outcome` 为准，前端从不自行判定。**
这条原则在修复前是"兜底"（过程漂了也不影响结算），修复后依然要保留 ——
它是纵深防御的第二层，不因为第一层修好了就撤掉。

### `ackBattle` 的 checksum 该怎么用

修复前的结论是"只能当遥测，不能当作弊判定"。修复后可以往前进一步，但**仍不能直接封号**：

| 用法 | 是否可行 | 理由 |
|---|---|---|
| 统计漂移率、按 UA/引擎版本聚合告警 | ✅ 推荐 | 这是发现"某新版引擎又变了"的唯一手段 |
| 不符时拒绝结算 | ❌ 禁止 | 结算本来就不依赖客户端 |
| 不符时判定作弊、封号 | ❌ 禁止 | 无法排除"未知引擎实现差异"这一无辜解释 |
| 不符时上报详细 trace 供排查 | ✅ 推荐 | 定位新的第二档函数回潮 |

> 这条必须写死在实现里。哪怕现在五个运行时全绿，
> 明天出现第六个运行时（新 V8 版本、鸿蒙 ArkWeb、某小程序容器）依然可能漂。
> **让无辜用户为环境差异背锅，是这类系统最容易犯也最难挽回的错误。**

### 副作用：一次性基准位移（必须升 `coreVersion`）

`detmath` 不是"等价替换"，是"换了一个同样正确、但不同的实现"。实测在 Node 上：

| 对比 | 与原生 `Math` 不等的比例 |
|---|---|
| `dsin(x)` vs `Math.sin(x)`（±40 rad 取 20 万点） | **24.96%** |
| `dcos(x)` vs `Math.cos(x)`（同上） | **25.80%** |
| `dpow(n/20, 0.5)` vs `Math.pow`（n=21..500） | **0%**（走 `Math.sqrt` 精确快路） |

差的只有 1 ULP，但确定性系统里 1 ULP 足以改变胜负——
一次索敌距离比较翻转，整场战斗就走上另一条路径。
PoC 基准因此从 **79 场 / 胜率 67%** 位移到 **80 场 / 胜率 69%**（多打出来一层）。

所以这是一次**回放不兼容的破坏性变更**，处理方式：

```ts
// src/backend/GameBackend.ts
export const CORE_VERSION = '4.1.0-detmath';   // 原 '4.0.0-poc'
```

并把判断标准固化下来 —— **`coreVersion` 不是发布版本号，是回放兼容性契约**：

| 改动 | 升不升 | 理由 |
|---|:--:|---|
| 引擎数学实现（`detmath.ts`） | ✅ 必须 | 哪怕只差 1 ULP |
| RNG 消费顺序 / 次数 | ✅ 必须 | 多摇一次骰子，后面全错位 |
| 平衡数值、技能公式、生成规则 | ✅ 必须 | 直接改结果 |
| 渲染 / UI / 音效 / 特效 | ❌ 不用 | 不进 checksum |

好消息是位移只发生这一次：往后 `detmath` 的输出不再依赖宿主引擎，
Supabase 升不升级 Deno、玩家用不用新版 Chrome，结果都钉死了。

## 9. 一句话总结

> **同引擎内确定性 ≠ 跨引擎确定性 ≠ 跨引擎版本确定性。**
>
> 第一层靠"不用 `Math.random`、不用 `Date.now`"；
> 第二层靠"不用规范允许近似的那批函数"；
> 第三层——最容易被忽略的一层——要求你意识到**你的服务端运行时也会升级**。
>
> 三层都做到之后，"后端算、前端放"才真的是一个可以签合同的承诺。
