## 1. 声学身份（Sonic Identity）

用三个形容词定义"这个游戏听起来是什么样"——所有后续决策以此为准：

| 词 | 含义 | 落地约束 |
|---|---|---|
| **冷峻克制** | 不堆砌华丽编曲，留白即张力 | 音乐以低频铺底 + 少量动机，不做满编制 |
| **打击优先** | 反馈爽不爽，先听打击点 | 所有命中/暴击/死亡的瞬态（attack）≤ 8ms，优先于旋律 |
| **自适应张力** | 声音跟着战局呼吸 | 单个 `CombatIntensity` 参数驱动铺底音量/滤波/层叠，不写死多套 BGM |

一句话定位：**"一场安静但每一击都清楚的生存试炼"**——安静是底色，清晰是底线。

## 2. 游戏状态 → 音频响应映射

| 游戏状态 | 音频任务 | 触发源 |
|---|---|---|
| 主菜单 / 编队 | 静默或极轻环境垫 | UI 交互 |
| 战斗进行中（非 Boss） | 打击层 + 轻铺底，随敌量涨落 | `CombatIntensity` |
| Boss 战 | 铺底加厚、低频下潜、专属技能音 | `isBoss` + `CombatIntensity` 顶满 |
| 胜利 | 大三和弦上行琶音 | `checkOver → win` |
| 失败 | 小调下行，余韵渐隐 | `checkOver → lose` |
| 中场商店（Intermission） | 轻快 UI 簇，无战斗铺底 | UI 交互 |
| 真空期（每 10 层） | 当前为**死代码**（见 §7 待决） | — |

## 3. SFX 事件清单与命名规范

### 3.1 命名规范

```
event:/[Category]/[EventName]
```

代码层（Web 实现）简化为扁平 id，但仍遵守分类前缀：

- `ui_*`  —— 界面（2D，居中，不参与空间化）
- `hit_*` / `crit` / `dodge` / `heal` / `shield_*` / `death_*` / `summon_*` —— 战斗反馈（世界空间，按 `x` 声像）
- `cast_*` —— 技能起手/结算（世界空间）
- `wave_start` / `victory` / `defeat` —— 状态转场（2D）

## 4. 集成契约（关键纪律）

**仿真只生产、绝不反向依赖音频**：

```ts
// battle.ts 内（纯数据汇，type-only import，不引入浏览器 API）
audioCues: AudioCue[] = [];
private emitAudio(cue: AudioCue) { this.audioCues.push(cue); }
drainAudioCues(): AudioCue[] { const c = this.audioCues; this.audioCues = []; return c; }
```

```ts
// ArenaCanvas.tsx 的 tick 循环后（消费在 sim 之外，零确定性影响）
const cues = sim.drainAudioCues();
for (const c of cues) audio.playCue(c);
```

- 所有音效经由 `audio.playCue(cue)` 事件接口，**禁止**在游戏逻辑里直接 `new Audio()` / 直接操作 `AudioContext`。
- 参数（声像 `x`、强度 `gain`）由仿真状态经 cue 传入，音色逻辑留在音频层。
- 同帧多 tick（定步长回放）累积的 cue 一次性消费，保持时序。

## 5. 音频架构（Web Audio，浏览器原生）

> 无 FMOD/Wwise（Web 运行时不适用）。以 Web Audio API 实现等价的中间件纪律：
> 事件系统 + 总线（VCA）+ 语音预算 + 空间化。

### 5.1 总线结构

```
                       ┌─ sfxBus   (战斗/技能，可被 intensity 调制)
AudioContext.destination ─ master ─┤ musicBus  (铺底/自适应，受 CombatIntensity 驱动)
                       └─ uiBus    (界面，永不被抢占)
```

每个总线为 `GainNode`，等同 FMOD 的 VCA：master 总控、music 随战局起伏、ui 恒最高。

### 5.2 语音预算与抢占

| 平台 | 最大语音 | 抢占策略 |
|---|---|---|
| Web/Desktop | 24 | 超限时抢占最旧、最低优先级 |
| Web/Mobile | 16 | 同上 |

- 优先级：`ui_*` / 状态音 = 0（永不被抢）；战斗反馈/技能 = 1（可抢）。
- 每个语音 `onended` 自动回收，活跃数实时计数。
- 基础音效为**程序化合成**（振荡器 + 噪声 + 包络），零采样文件依赖 → 无加载、无 404、可离线。

### 5.3 空间音频（2D 竞技场模型）

俯视 2D 竞技场不做 HRTF/3D，采用**立体声声像 + 距离衰减**：

```
pan = clamp((cue.x / arena.W) * 2 - 1, -1, 1)   // 左 -1 / 中 0 / 右 +1
```

- `ui_*` / 状态音：`pan = 0`（居中）。
- 世界音：`x` 缺省时回退居中。
-  occlusion / 混响分区：当前**未实现**（标记 stretch），架构预留 `audio.setReverb(zone)` 接口。

## 6. 自适应音乐参数

单一权威参数驱动全部音乐响应，避免多参数打架：

### `CombatIntensity`（0.0 – 1.0）

| 值 | 含义 | 音乐响应 |
|---|---|---|
| 0.0 | 无敌人（清场间歇） | 仅极轻铺底 |
| 0.3 | 交战开始 | 铺底加厚、低频下潜 |
| 0.6 | 多敌/Boss 在场 | 叠动机层、滤波打开 |
| 1.0 | Boss 全力 | 最大张力、临场感顶满 |

- **源**：`alive('enemy').length` + `isBoss` 加权（游戏系统每帧写入）。
- **更新**：每 0.5s 平滑 lerp，量化到节拍边界（基础音效无节拍，故仅做 lerp 平滑）。
- **接口**：`audio.setIntensity(v)` → 调制 `musicBus` 增益与铺底滤波器截止。

> 当前 v1.5 基础实现：铺底为程序化低频 drone，`setIntensity` 提升其增益与明亮度；完整分层 stem 音乐为后续需求。

## 8. 性能预算

| 项 | 预算 |
|---|---|
| 最大并发语音 | 24（桌面）/ 16（移动） |
| 单 SFX 时长 | ≤ 0.5s（程序化，自动回收） |
| 铺底 CPU | < 0.3ms/帧（2 振荡器 + 低通 + LFO） |
| 首声延迟 | 手势解锁后 < 20ms（无采样加载） |
| 内存 | 程序化零常驻采样；仅复用噪声 buffer |
