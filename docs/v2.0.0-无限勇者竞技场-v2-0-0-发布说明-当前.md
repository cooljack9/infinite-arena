# 无限勇者竞技场 v2.0.0 发布说明（当前基线 · 版本体系统一）

> ⚠ **版本体系已统一**：本仓自 **v2.0.0** 起收敛为**单一版本轴线** —— `package.json` 的 `version`、`CORE_VERSION`、git tag、压缩包名、线上 Pages，以及**全部文档的版本声明**，共用唯一号 `2.0.0`。本文及他处出现的其它 `vX.Y.Z`（如 `v1.9.0` / `v3.1.0` / `4.0.0` / `4.2.0-van`）均为**历史里程碑代号**，不再具有发布号效力（详见 `docs/INDEX.md`「版本体系」）。

## 一、本次发布的核心：四套编号 → 一套 `2.0.0`

此前本仓同时存在四条各自独立演进的版本线，互相对不齐，git 历史与文档处处打架：

| 旧编号体系 | 旧值 | 含义 | 现状 |
|---|---|---|---|
| 本地版线（README / docs） | `v1.9.0` | 前端本地版发布号 | **作废** → `2.0.0` |
| 后端交付线（docs/backend） | `v3.1.0` | 后端交付产物版本 | **作废** → `2.0.0` |
| 包版本线（package.json） | `4.0.0` | npm 包发布版本 | **作废** → `2.0.0` |
| 回放契约线（CORE_VERSION） | `4.2.0-van` | 跨运行时回放兼容性契约 | **作废** → `2.0.0` |

v2.0.0 起，以上四者**合并为同一个 `2.0.0`**，不再分叉。任何一次发布，四个位置必须同时等于 `2.0.0`。

## 二、⚠ 破坏性变更（上线须知）

`CORE_VERSION` 由 `4.2.0-van` **号段回退**为 `2.0.0`。这是一次**破坏性收敛**：

- `CORE_VERSION` 是**回放兼容性契约**，不是发布号。它烘焙进 `supabase/functions/_shared/core.js`，前端用它比对 `checksum` 监测版本漂移。
- 号段回退意味着**所有旧的 replay 与旧存档一律不可复用**——引擎仍按 `battleSeed` 确定性演算，但契约号变了，前端会撞到 `VERSION_MISMATCH` 并提示刷新，这正是预期行为。
- **上线动作（必须执行其一）**：
  1. 清库（丢弃旧 runs / 旧 meta 快照），或
  2. 强制所有客户端刷新到 `2.0.0` 后再允许进入。
- 不做清库也不强制刷新 = 线上新旧契约并存、replay 校验大面积失败。**这是事故，不是特性。**

> 历史存档推演：v4.2.0-van 之前的存档（v4.1.0-detmath 等）本就因契约号不连续而不可复用；本次统一到 `2.0.0` 一并归零，反而让契约号从「永不回退」回归「随发布号走」，长期更易维护。

## 三、新规则（单一版本轴纪律）

1. **`CORE_VERSION` 必须恒等于 `package.json` 的 `version`**，二者不一致即视为事故；`npm run verify` 的 `guard` 步骤会拦截。
2. 任何触及 `packages/core/` 的改动一律**整体升号**：升发布号 = 升 `CORE_VERSION` = 升 git tag = 升压缩包名 = 升文档声明，五处同步，不再有独立的回放契约号。
3. 历史文档文件名中保留的旧版本号（如 `v2.9.13-发布说明.md`、`v3.1.0-发布说明.md`）**仅为历史文件名 / 里程碑代号，不具发布号效力**；当前唯一基线为 `2.0.0`。
4. `supabase/functions/_shared/core.js` 由 `npm run build:core -- --sync` 从 `packages/core/src` 重新烘焙生成，**不是手改文件**；`CORE_VERSION` 的真相源在 `packages/core/src/contract/index.ts`。

## 四、本次实际改动清单

- `package.json` / `package-lock.json`：`4.0.0` → `2.0.0`。
- `packages/core/package.json`：`4.2.0-van` → `2.0.0`。
- `packages/core/src/contract/index.ts`：`CORE_VERSION` `4.2.0-van` → `2.0.0`（`@arena/core` 真相源）。
- `supabase/functions/_shared/core.js`：由 `build:core --sync` 重新生成，`CORE_VERSION` 落到 `2.0.0`（修复了此前与源码 `4.1.0-detmath` 不一致的漂移）。
- `supabase/functions/_shared/core-types/contract/index.d.ts`：类型声明镜像 `CORE_VERSION` 同步为 `2.0.0`。
- 全部 docs（`README.md`、`ARCHITECTURE.md`、`CICD.md`、`CI-CD规范.md`、`docs/backend/*` 及历史发布说明）版本声明统一改写为 `2.0.0`，并补「版本体系已统一」声明。
- 字节级重复文件归档至 `docs/archive/` 与 `docs/backend/archive/`（内容一致，仅留一份用于日常查阅）。
