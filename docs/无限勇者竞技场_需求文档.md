## 1. 项目概述

### 1.1 一句话定义

> 一支由 **3 名勇者起步、可扩编至 7 人** 的队伍，进入不断升级的「挑战杯」竞技场赛制，在永久死亡与随机增益的约束下，挑战没有终点的无尽层，比拼「你能走多远」。

### 1.2 设计目标

1. **把「公会经营」压成「小队闯关」**：去掉长线经营负担，让单局 5–15 分钟就能进入核心爽点，死局即重开。
2. **阵容规模即战力**：3 人起队、7 人满编是数值与战术的基底（职业搭配、站位、羁绊），队伍规模既是成长线也是策略边界。
3. **难度复利 + 随机构筑**：用可量化的难度曲线制造「再来一局」的留存钩子，用随机遗物/天赋让每局都不一样。
4. **低成本高重玩**：用有限内容（敌人模板、遗物、事件）撬动近乎无限的可重玩局，控制美术与关卡产能。
5. **排行榜即终点**：不做剧情终点，用赛季排行榜把「没有终点」变成可不断刷新的成绩。

### 1.3 目标用户

| 群体 | 特征 | 核心诉求 | 对应系统 |
|---|---|---|---|
| 肉鸽硬核 | 玩过《杀戮尖塔》《哈迪斯》《吸血鬼幸存者》 | 构筑深度、极限层数 | 遗物/天赋、无尽缩放 |
| 战棋/自走爱好者 | 玩过《角斗士公会经理》《云顶》 | 阵容克制、站位博弈 | 多单位站位、职业羁绊 |
| 轻度竞技玩家 | 爱看排行、晒战绩 | 社交比较、赛季目标 | 全球/好友排行榜 |
| 联机休闲 | 拉朋友开黑 | 合作破局、分工 | 3 人协作模式 |

### 1.4 参考标杆拆解（为什么要参考它们）

| 标杆 | 借鉴点 | 本作落地方式 |
|---|---|---|
| 角斗士公会经理 · 挑战杯/无尽锦标赛 | 赛制名次、自动战斗回放、敌人逐轮变强、Steam 排行榜 | 「挑战杯」分段赛制 + 自动战斗 + 层间敌人成长 + 赛季榜 |
| 角斗士公会经理 · 组队 | 战士/游侠/野兽/法师搭配、特质、装备、天气 | 多职业槽位（4 大类 9 子类）+ 特质 + 装备 + 战场环境 |

## 2. 核心概念

### 2.1 玩法循环（单局 Run）

```
[组建队伍（3 人起队，可扩至 7 人）] → [进入挑战杯·第 N 层]
   → [战前布阵 + 选增益] → [自动战斗] → [胜负判定]
        ├─ 胜：获得遗物/金币/天赋点 → 进入 N+1 层（敌人更强）
        └─ 负 / 全灭：本局结束 → 结算层数与积分 → 写入排行榜 → 元进程结算
```

### 2.2 队伍规模：三人起队，七人满编

| 维度 | 含义 | 设计约束 |
|---|---|---|
| **规模成长（核心）** | 开局 **3 人** 入场（呼应「三人进入竞技场」），随挑战杯推进/招募/元进程可扩编至 **7 人** 满编 | 出战名额即战力上限，扩编是核心成长线之一 |
| **玩家维度（多人）** | 支持 **3 名玩家** 协作，每人操控 1+ 名勇者 | 协作模式专用难度与分工机制 |

> 文档默认以「单人操控 3–7 人队伍」为主模式，第 8 节定义可选的 3 人协作联机模式。

> **【v1.3 硬约束 · 开局编队】** 主模式开局编队界面（TeamBuilder）**锁定为「恰好选择 3 名勇者」方可出战**，呼应「三人进入竞技场」：不允许 1–2 人或 4–7 人开局。中期扩编至 7 人为可选成长线（见 §5.1），但**开局强制三人**。

### 2.3 设计支柱（Design Pillars）

1. **每局不同**：随机遗物 + 随机事件 + 随机敌人组合。
2. **越深越狠**：难度曲线可感知、可预测、但不可逆。
3. **阵容规模即策略边界**：从 3 到 7 的扩编过程，站位、职业羁绊、技能链是核心博弈，而非纯堆数值。
4. **死得快，开得也快**：单局周长可控，死亡无惩罚性挫败，元进程只增不减。

## 3. 世界观与背景

> 设定为轻量、可快速代入的幻想竞技世界，不铺长线剧情（无尽模式无需主线终点）。

- **背景**：「勇者竞技场」是诸神设立的试炼场。每支小队被投入不断坍塌重组的擂台，向上攀登无尽层。
- **叙事钩子**：层越深，敌人越像「上一支陨落小队的残影」——用低成本文本叙事强化「前人都倒在这里」的压迫感。
- **赛季主题**：每赛季更换一个「天象/诅咒」主题（如「血月」「锈蚀」「虚空」），影响全局规则，保持新鲜感。

## 4. 核心玩法循环（详细）

### 4.1 单局生命周期

| 阶段 | 玩家操作 | 系统行为 | 时长（目标） |
|---|---|---|---|
| 组队 | 从已解锁勇者中组建队伍（开局 3 人，可扩至 7 人）、配装备/天赋 | 校验阵容合规（规模/职业/羁绊） | 0.5–1 min |
| 入场 | 查看本层敌人预览、环境 | 生成第 N 层配置 | 即时 |
| 战前 | 布阵（前/中/后排）、选本层增益 | 应用增益、结算羁绊 | 0.5–1 min |
| 战斗 | 观战 + 关键时刻手动触发大招/技能（半即时） | 自动战斗演算 | 1–3 min |
| 结算 | 领取奖励、决定是否继续 | 难度递增、存档快照 | 即时 |
| 终结 | 查看战绩、元进程结算 | 写榜、发赛季积分 | 即时 |

### 4.2 「挑战杯」赛制结构（参考角斗士公会经理锦标赛）

将无尽层划分为**赛段（Cup Segment）**，每赛段 = 固定层数（建议 10 层），内部分级：

| 赛段 | 层数区间 | 赛制特征 |
|---|---|---|
| 资格赛 | 1–10 | 敌人弱、教学引导、奖励丰厚 |
| 晋级赛 | 11–30 | 引入精英、环境事件 |
| 大师赛 | 31–60 | 每 10 层设「突变层」（规则重写） |
| 传奇赛 | 61+ | 伪无尽软上限、Boss 密度提升 |

- **名次/积分**：每层按「剩余血量、用时、连胜」计算层积分，累计为杯赛总分，用于赛季排行榜。
- **真空期机制**（借鉴塔防波次设计）：每赛段末（如第 10/20/30 层）出现「强度真空」——敌人血量 -40% 但移速 +200%，惩罚纯龟缩阵容，逼迫保留机动输出。

### 4.3 无尽层递进（Roguelike 无尽算法）

采用**混合缩放**：前期线性适应、中期指数复利、后期混沌突变，避免「前 50 层割草、50+ 断崖」的阈值天花板。

- **适应期（1–20 层，线性）**：敌人 HP ×(1+0.08n)，伤害 ×(1+0.06n)。
- **复利期（21+ 层，指数）**：HP ×1.12^(n−20)，伤害 ×1.10^(n−20)（近似 `1.3^n` 思路的温和版，防止过早数值溢出）。
- **突变层（每 10 层强制）**：触发一条「混沌规则」（如禁用某职业大招 3 层 / 全场持续掉血 / 敌人窃取遗物效果），参考《死亡细胞》细胞机制「重写关卡生成规则」，防止 build 一招鲜吃遍天。
- **伪无尽软上限**：60 层后稀有遗物掉落衰减、敌人组合转为实时演算，引导玩家在「收益拐点」前体面收手（参考实测：73% 玩家在 30–35 层因「收益断崖」主动退出，需用真空期与突变制造继续理由）。

### 4.4 综合关卡设计（竞技场布局 · 遭遇编排 · 环境叙事）

> **关卡设计纲领（Level Design Mandate）**：把「无尽层」从一串难度数字，做成**有空间、有节奏、有叙事、可读可学**的竞技场序列。每条规则以「玩家进场 3 秒内应理解什么」为校验标准。

#### 4.4.1 设计三原则

1. **可读优先（Readability First）**：玩家进场 3 秒内必须识别——敌人在哪、目标/机制是什么。自动战斗回放前必须有「敌我预览 + 环境预告」（已在 4.1 / 5.5 定义），杜绝「看不见就被秒」。
2. **节奏呼吸（Pacing Breath）**：每层在「tension 激战 → release 喘息/奖励 → escalation 升级」间循环，**禁止连续 3 层同强度**。
3. **空间即叙事（Space = Story）**：层越深场景越像「上一支陨落小队的残影」——用布局、道具、光照讲低成本故事（见 4.4.5）。

#### 4.4.2 竞技场布局原型（Arena Layout Archetypes）

布局由程序在原型库中按规则抽取（见 4.4.6），保证变化又不失控。共 6 种原型：

| 编号 | 原型 | 尺寸（约） | 特征 | 战术偏向 | 环境叙事 |
|---|---|---|---|---|---|
| A1 | 圆形竞技场 | ⌀24m | 对称、开阔、无遮蔽 | 均衡、近战贴脸 | 经典角斗场，万人欢呼 |
| A2 | 破碎长廊 | 8m×40m | 窄道、单侧掩体 | 远程/控制、卡位 | 被攻破的城墙通道 |
| A3 | 立柱迷宫 | 28m×28m | 密集石柱掩体、可绕后 | 突进/刺客、包抄 | 坍塌的神庙中庭 |
| A4 | 双层看台 | 下层 30m×20m + 高台 | 高低差、远程优势位 | 射手/狙击、制高 | 贵族观战包厢 |
| A5 | 浮岛裂隙 | 多块浮板 + 虚空 | 站位即生死、位移压力 | 灵活/位移职业 | 崩解的试炼虚空 |
| A6 | 对称角斗场 | 两侧各 20m×16m | 双出生点、中央 Boss 台 | Boss 战、对位 | 诸神终审之台 |

**Blockout 规范示例（A3 立柱迷宫）**：

```
房间：A3 立柱迷宫
尺寸：28m × 28m × 10m（高）
掩体：6× 石柱（⌀1.2m，高 3m），非对称矩阵，提供 prospect-refuge
高台：无（偏向地面缠斗）
光照：暖色主光自南（指引敌方出生点），冷色补光自柱隙（对比提升可读性）
入口：西（我方）/ 出口：东（敌方全灭即胜，无物理出口）
环境叙事：中央倒伏旗杆 + 焦痕地面 = 上一队在此团灭
可读性：敌方出生点红地纹标记，进场即见；所有石柱不遮挡敌我初始可见线
```

> 所有布局在 **grey box（灰盒）阶段** 即校验：无地图的新玩家能否判断敌我方位。未过校验的布局禁止进入美术。

#### 4.4.3 遭遇模板与波次编排（Encounter Templates）

每层由 1–N 波组成；敌人按 **与玩家同构的 4 类（坦/战/射/法）** 生成，保证「克制关系可读」——玩家看到敌方构成即可反制布阵。

| 赛段 | 波数 | 敌方构成模板（示例） | 战术可选项 | 撤退位 |
|---|---|---|---|---|
| 资格赛 1–10 | 1 波 | 2 战 + 1 射 | 正面 / 侧翼包抄 | 入场拱门 |
| 晋级赛 11–30 | 2 波 | 1 坦 + 2 战 + 1 法 / 2 射 + 1 控 | 集火优先级、控场反打 | 中场掩体 |
| 大师赛 31–60 | 2–3 波 | 含 1 精英（突变层触发） | 多线作战、保命位 | 立柱/高台 |
| 传奇赛 61+ | 3 波 + Boss | 实时演算组合 | 极限构筑、走位 | 浮岛边缘 |

**遭遇设计硬性约束（每条遭遇必须满足）**：
- **进场可读**：所有敌人交战距离前可见（预览已覆盖，此处约束生成逻辑不出现「不可见即被秒」）。
- **≥2 种战术选项**（如集火 vs 控场、正面 vs 绕后）。
- **≥1 个 fallback 位**（掩体/高台/入场点）供残血单位周转。
- **难度预算**：本层敌总战力 = 玩家预期战力 × 缩放系数（见 6.1），防超模。

#### 4.4.4 流程与节奏图（Flow & Pacing）

单局宏观流（层内 micro-loop 见 4.1）：

```
[入场·读布局] → [布阵·看预览] → [战斗·激战] → [结算·喘息+奖励]
      ↑                                                │
      └──────── 继续？是 → 下一层（更强+新原型） ──────┘
                  否 → 终结·写榜
```

单局张力曲线（tension 0–100）：

```
层:    1 — 5 —10 —15 —20 —25 —30 —35 —40 —45 —50 —55 —60 —65 —70
张力:  20  40  60  50  70  55  80  60  85  65  90  70  95  80  99
标记:  教   资   真   事   突   事   大   真   突   事   传   真   传   真   传
说明: 资格赛缓升 / 每赛段末真空期(↓)喘息 / 每10层突变层(↑)加压 / 大师赛后仅升不降
```

> 真空期（第 10/20/30… 层）张力强制回落至 50–60，制造「差一点就过了」的再来一局动力；突变层张力跳升，打破固化构筑。

#### 4.4.5 环境叙事（Environmental Storytelling）

每条层用 **≤3 件** 叙事道具讲一个瞬间：
- **残影旗杆 / 破碎武器**：上一队在此倒下 → 「你也可能」。
- **未熄篝火 / 空药瓶**：有人曾短暂喘息 → 暗示此处曾是安全点。
- **倒置观战席**：诸神已离场，只剩你与深渊。
- 叙事强度随层数递增，深层用「成堆残骸 + 暗红光照」强化压迫，但**永不遮挡可读性热区**。

#### 4.4.6 程序生成规则（Procedural Generation Rules）

无尽模式靠程序生成，但必须守质量下限：

**生成文法（Grammar）**：
```
层 = 锚点层? + 原型抽取 + 遭遇预算 + 环境修饰
锚点层（强制固定）：赛段末=真空期层；每10层=突变层；赛段节点=Boss层
原型抽取：从 A1–A6 按权重抽，禁止连续 3 层同原型
遭遇预算：敌总战力 = 玩家预期战力 × 缩放(6.1) × 赛段倍率
环境修饰：叙事道具库随机挂接，不覆盖可读性热区
```

**质量阈值（自动校验，不达标不出）**：

| 指标 | 阈值 |
|---|---|
| 可读性 | 进场 3s 内敌我方位可辨（红/蓝地纹） |
| 可达性 | 所有敌方出生点在我方单位可达范围内（无卡死） |
| 多样性 | 连续同原型 ≤2 层；连续同机制 ≤2 层 |
| 难度单调 | 敌总战力非递减（n+1 ≥ n，真空期除外） |
| 战术冗余 | 每层 ≥2 战术解、≥1 fallback 位 |

**关键路径锚点（Critical Path Anchors）**：Boss 层与真空期层为手工锁定布局，其余程序填充——兼顾「可控的里程碑」与「无限的变化」。

#### 4.4.7 可读性核对清单（Readability Checklist）

每层生成后自动跑此清单，全绿才允许进入战斗：

- [ ] 进场 3 秒内可指出敌方出生点（红地纹）
- [ ] 本层机制（真空/突变/环境危害）战前有文字 + 图标预告
- [ ] 所有敌人交战前可见，无「隐身即秒」
- [ ] 至少 1 个 fallback 掩体/高台，且不与敌方初始视线重叠
- [ ] 叙事道具未遮挡核心战斗热区
- [ ] 难度预算符合 6.1 缩放，未超模
- [ ] 与前一层原型/机制不重复（多样性阈值）
- [ ] **（v1.4）本层主题皮已应用，且地面/掩体/单位三层色值对比度 ≥ 3:1**

#### 4.4.8 地图风格化：主题皮系统（v1.4 新增）

**要解决的问题**：现在 30 层打下来，A1 / A3 / A6 三张灰扑扑的图轮着上，玩家的空间记忆是「我打了三十层同一个地方」。无尽模式最贵的资产是**深度感**——玩家必须能说出"我打到冰区了"，而不是"我打到 23 层了"。层数是数字，区域是记忆。

**核心手法：主题与布局正交**。布局（A1–A6）管 tilemap 和战术，主题（Theme）管配色、掩体外观、环境点缀。**6 主题 × 6 布局 = 36 种视觉组合**，成本只有 6 套配色表。

|---|---|---|---|---|---|---|

**设计决策与 rationale**

| 决策 | 选择 | 为什么不是别的 |
|---|---|---|
| 主题切换粒度 | **每 10 层换一次**，不随机 | 随机会毁掉空间记忆。10 层 ≈ 一个赛段（§4.2），和赛制节奏对齐，玩家能形成「过一个赛段换一个世界」的期待 |
| 主题与布局关系 | 正交，互不约束 | 若绑定（如熔火只出 A3），会同时损失布局多样性和主题多样性。正交是这里唯一划算的选择 |
| 50 层之后 | 主题**循环重跑**，但每轮叠加「褪色」滤镜：色相 −8°、饱和 ×0.9、亮度 ×0.96 | 无限模式必须能无限跑。滤镜叠加把「循环」变成「越走越荒芜」的叙事——第三轮沙岩已经是灰白色了，这本身就在讲故事（§4.4.5 空间即叙事） |
| 地面棋格 | 主/次色交替 24px 棋格，对比度控制在 **1.15:1 以内** | 棋格给移动提供距离参考（玩家能数格子判断射程），但对比度一高就抢单位的视觉焦点。1.15:1 是"看得出但不刺眼"的经验区间 |

> **硬约束（可读性红线）**：任何主题下，**地面色 ↔ 掩体色 ↔ 单位主色**三者两两对比度必须 ≥ 3:1（WCAG AA 非文本标准）。虚空主题最危险——深色背景 + 深紫单位 = 糊成一团。虚空主题下所有单位强制加 1px 亮边描边。这条进 §4.4.7 核对清单。

> `[PLACEHOLDER · 主题切换层数 10]` **假设**：玩家平均单局能到 18–25 层，即一局能见到 2–3 个主题。**验证路径**：埋点统计玩家单局到达层数的 P50/P75；若 P50 < 12，说明大部分玩家一辈子只见得到沙岩区，那 10 层的粒度就太粗，要压到 6 层；若 P50 > 30，可放宽到 12 层以延长新鲜感。

**实现落点**：`ArenaDef.theme: MapTheme` 定义于 `src/types.ts`；主题表在 `src/game/content/arenas.ts`；渲染分支在 `src/render/ArenaCanvas.tsx`（地面/墙/掩体绘制 + 环境粒子层）。

## 5. 系统模块详细设计

### 5.1 队伍规模与编队系统（核心）

**规模成长线**：开局 **3 人** 入场（呼应「三人进入竞技场」），通过赛段奖励、招募事件、元进程解锁，出战名额逐步扩至 **7 人** 满编。扩编本身是核心成长反馈。（注：**开局编队界面强制恰好 3 人**，见 §2.2 硬约束。）

| 要素 | 规格 |
|---|---|
| 出战上限 | 初始 3（**开局编队界面锁定恰好 3 人，不可多不可少**），满编 7；阵亡名额 = 战力缺口，可用「替补/召唤」机制临时补位 |
| 编队位 | 前排 / 中排 / 后排，影响被集火概率、技能射程、羁绊触发 |
| 站位网格 | 建议 3 排制：前排≤3（坦/战）、中排≤2（战/射）、后排≤2（射/法）；多余单位自动归入最近可用排 |
| 职业覆盖 | 建议覆盖「坦-输出-辅」三角；7 人时可组建双坦双辅多输出阵 |
| 羁绊 | 同系/特定组合触发被动（如「双游侠=暴击联动」「战牧=护盾共享」「双法=增益共鸣」） |
| 特质 trait | 每名勇者带 1–2 个特质（角斗士公会经理式），提供加成或额外技能，可升级 |
| 招募（局内） | 深层可通过「佣兵事件」临时加入第 4–7 人，死局不影响元进程 |
| **同名多份（v1.4 / v1.7 强化）** | **允许**同一 `heroId` 的多份角色同时上场，互相独立结算（装备/成长/升星全按 uid 记账）；第 2 份起名字加罗马数字后缀 + 臂章像素区分（§5.7.4）；**v1.7 起重复招募 = 新增一份副本（不升星），升星/突破走 `upgradeHero`，并支持 `sellHero` 出售不需要的副本**（见 §17.1） |
| **升星（v1.4）** | 编队界面拖拽两名同 `heroId` 角色合并升 1 星，上限 5 星；被合并者装备退回背包（§5.7.3） |
| **体型（v1.4）** | 每名勇者带一个体型（巨躯/魁梧/标准/轻捷/精巧），影响生命、移速、受击体积与一条体型特性（§5.2.1） |

### 5.2 职业体系（4 大类 · 9 子类）

职业分 **4 大类**，每类含 2–3 个子类，共 **9 个子类**。每个子类有清晰的**主属性偏向**与**二级属性定位**，决定其从一级属性获益的方式（详见 5.3）。**v1.4 起追加第三条身份轴：体型（Body Type）**，见 §5.2.1。

| 大类 | 子类 | 定位 | 主属性偏向（强壮/力量/敏捷/智力） | 二级属性侧重 | 默认体型 | 普攻射程(格) | 技能射程(格) |
|---|---|---|---|---|---|---|---|
| **坦克** | 物理坦克 | 前排承伤、物理减伤、嘲讽 | 强壮★★★★ 力量★★ | 生命、物理减伤、仇恨 | 巨躯 | 1.1 | 3.0 |
| | 魔法坦克 | 前排承伤、魔法减伤、护盾 | 强壮★★★★ 智力★★★ | 生命、魔法减伤、护盾 | 魁梧 | 1.1 | 0（自身） |
| **战士** | 冲锋物理 | 突进爆发、近身收割 | 力量★★★★ 敏捷★★★ | 物理伤害、移速、攻速 | 魁梧 | 1.1 | 6.0 |

> **技能射程 vs 普攻射程的定档原则**：`技能射程 ∈ [普攻射程 × 1.0, 普攻射程 × 1.5]`，且**近战单位的技能射程必须 ≥ 2.5 格**。理由：大招若够不到普攻够不到的地方，走位上就没有战术价值；而近战大招若和普攻同为 1.1 格，玩家永远看不出「他放了技能」和「他普攻了」的差别。物理坦克 1.1 → 3.0 是这条原则最典型的应用——嘲讽必须能拉到后排，否则技能作废。

- **勇者池**：首版每子类 1–2 名，共 **12–16 名** 勇者，含基础属性、成长曲线、专属技能、特质、**体型**。
- **养成（局内）**：战斗中获取「天赋点」升级技能等级 / 解锁分支。
- **养成（元进程）**：账号级解锁新勇者、提升基础属性上限（见第 7 节）。

#### 5.2.1 体型系统（Body Type · v1.4 新增）

**为什么要有体型**：体型不是皮肤，是**读盘信息**。自动战斗里玩家不操作单位，唯一能做的就是看——他必须在 1 秒内从场上一堆 16px 小人里认出「谁能扛、谁会溜、谁一碰就碎」。换色做不到这件事（色盲玩家直接出局，深色主题下也会糊成一片），**只有轮廓尺寸能做到**。所以体型必须同时改三件事，缺一件就退化成装饰：**像素尺寸 / 属性系数 / 受击体积**。

**五档体型规格**

| 体型 | 代号 | 像素占格 | HP 系数 | 移速系数 | 受击半径系数 | 闪避修正 |
|---|---|---|---|---|---|---|
| 巨躯 | `colossal` | 20×20（1.25×） | ×1.35 | ×0.80 | ×1.30 | −4% |
| 魁梧 | `heavy` | 18×18（1.125×） | ×1.18 | ×0.90 | ×1.15 | −2% |
| 标准 | `medium` | 16×16（1.00×） | ×1.00 | ×1.00 | ×1.00 | ±0 |
| 轻捷 | `light` | 14×14（0.875×） | ×0.88 | ×1.12 | ×0.88 | +3% |
| 精巧 | `petite` | 12×12（0.75×） | ×0.75 | ×1.25 | ×0.75 | +6% |

**数值 rationale（每个系数的来历，不是拍脑袋）**

| 系数 | 设计逻辑 |
|---|---|
| HP 阶梯 ±12~15%/档 | 做成**单调递减的等差阶梯**（1.35/1.18/1.00/0.88/0.75），相邻档差约 0.12–0.17。玩家不需要背表，只要记住「大一档大概多扛 15% 血」。 |
| 移速与 HP 严格互逆 | 移速阶梯（0.80/0.90/1.00/1.12/1.25）与 HP 阶梯方向相反、幅度相当。**体型是一条单轴权衡：生存 ↔ 机动**，不允许出现「又大又快」的支配档位。 |
| 受击半径 = 像素尺寸 | 视觉即判定。看起来 1.25 倍大的单位，AoE 判定就是 1.3 倍大。绝不做「看着大但打不中」的欺骗性碰撞盒——那是自动战斗玩家最容易骂"这游戏在骗我"的地方。 |
| 闪避修正压在 ±6% | 二阶微调，仅用于强化手感认知。**上限刻意压死**：精巧本体已有 +25% 移速和 0.75 体积，闪避若再给 +15%，小体型叠敏捷会直接免疫远程，把射手职业打成废物。 |
| 极端跨度 1.35 / 0.75 = 1.8× | 单看 HP 跨度确实大，但对应付出 0.80 / 1.25 = 0.64× 的移速代价 + 1.30 / 0.75 = 1.73× 的挨打面积。三项相乘后有效生存力跨度实际约 1.35×1.25/1.30 ≈ 1.30 vs 0.75×0.80/0.75 ≈ 0.80，即 **1.6× 而非 1.8×**。 |

> `[PLACEHOLDER · HP/移速/体积三档系数]` **假设**：单局平均 20 分钟、平均遭遇 4.2 秒完成一次索敌位移。**验证路径**：跑 500 次 30 层 Monte Carlo，统计各体型单位的「有效承伤 / 阵亡时刻中位数」，若巨躯与精巧的阵亡时刻中位数差距 > 40%，则把 HP 阶梯从 ±15% 压到 ±10%。若测出平均单局其实是 35 分钟，深层站桩比例上升，体积惩罚会被放大，整套系数要重画。

**体型专属特性（每档 1 条，只在明确场景触发）**

| 体型 | 特性名 | 效果 | 为什么是这条 |
|---|---|---|---|
| 巨躯 | 压迫 | 自身免疫击退；相邻（≤1.5 格）敌方受到的击退效果 −50%。代价：被 AoE 命中的判定半径 +30%（已计入受击系数） | 把「大」翻译成战场功能：巨躯是一个会移动的地形，卡住敌人的位移 |
| 魁梧 | 稳桩 | 单次受伤 ≥ 15% 最大 HP 时，随后 1.5s 内减伤 10% | 抗爆发而非抗平砍——魁梧是次级坦克位，怕的是被秒不是被磨 |
| 标准 | 通用 | 无修正，所有系数 = 1.0 | **这本身就是设计价值**：给全套数值一个调参锚点。任何"标准也得有点东西"的冲动都要拒绝 |
| 轻捷 | 滑步 | 每次闪避成功后 0.8s 内移速 +20% | 奖励已经发生的好运，制造「越躲越滑溜」的连锁手感 |
| 精巧 | 难瞄 | 与攻击者距离 ≥ 4 格时，受到的**远程**伤害 −8% | 只在远距离生效，逼精巧单位保持风筝距离，被贴脸就没有这条 |

**每条特性只在一个可描述的场景触发**——玩家能形成「什么时候这个体型有用」的判断。不给全时段无条件被动，那种东西等于隐形数值，玩家感知不到，只会让平衡表更难看懂。

**体型与职业的关系：体型是第二身份轴，用来做「同子类不同角色」的功能拆分**

同一个子类可以出多种体型的勇者，这是勇者池扩展到 12–16 名的主要手段：

| 示例 | 体型 | 玩法差异 |
|---|---|---|
| 枪炮手·重装型 | 魁梧 | 移动炮台，站得住、走得慢，适合前中排火力压制 |
| 枪炮手·游击型 | 轻捷 | 边走边打，拿不住线但难被集火，适合后排风筝 |
| 物理坦克·巨躯 | 巨躯 | 卡位型主坦，用体积挡路 |
| 物理坦克·魁梧 | 魁梧 | 副坦，能跟上队伍推进节奏 |

> **约束**：体型**不改射程、不改攻速、不改伤害**。只管生存 / 机动 / 体积三件事 + 一条特性。守住这条边界，体型才是可读的一条轴；一旦允许体型改伤害，它就会变成第二套职业系统，与 §5.2 打架。

#### 5.2.2 召唤师专章：三类召唤物（v1.4 新增）

原设计「召唤石像 = 召唤 1 个 150%INT 属性的通用单位」有一个致命问题：**它不产生任何玩家决策**。召唤物做什么、去哪、能改变什么战局，玩家事前不知道、事后也说不清。v1.4 把召唤物拆成三类，每类服务一个明确的战场缺口。

| 召唤物 | 代号 | 体型 | 战场角色 | HP | 攻击 | 移速 | 射程 | 持续 |
|---|---|---|---|---|---|---|---|---|
| 石魂卫 | `bulwark` | 魁梧 | 肉盾类：挡刀 + 吸仇恨 | 220% INT | 60% INT | ×0.75 | 1.1 格 | 18s |
| 影刃仆 | `sprinter` | 精巧 | 极速冲刺类：切后排 / 收割 | 80% INT | 130% INT | ×1.60 | 1.1 格 | 10s |
| 咒火灵 | `arcanist` | 轻捷 | 远程攻击类：持续消耗 | 90% INT | 110% INT | ×1.00 | 5.5 格 | 14s |

**数值 rationale**

- **HP × 攻击 的乘积近似守恒**：220×60 = 13200 / 80×130 = 10400 / 90×110 = 9900。肉盾略高是因为它的攻击几乎不产出（60% INT 打不死人），把预算还回生存是合理的。
- **持续时间与定位挂钩**：石魂卫 18s（要撑过一整个交火窗口才有意义）、影刃仆 10s（冲刺型只在窗口期有用，长了就是站场刷屏）、咒火灵 14s（消耗需要时间累积但不该盖过本体）。
- **移速 ×1.60 是全场最快**：影刃仆必须**明显快过所有玩家单位**，否则「极速冲刺」这四个字在屏幕上看不出来。视觉承诺必须由数值兑现。

**选型规则（自动战斗必须可播报）**

```
召唤时按优先级判定，命中即出，并在战斗日志打出理由：

1. 我方存活坦克数 == 0            → 石魂卫   日志：「阵线告急 → 召唤石魂卫」
2. 敌方存在 HP < 40% 的单位        → 影刃仆   日志：「捕捉残血 → 召唤影刃仆」
3. 否则                           → 咒火灵   日志：「战线胶着 → 召唤咒火灵」

保底轮换：连续两次召唤不得为同一类型。若规则判定重复，取优先级次高的一类。
```

> 自动战斗里最忌讳「召唤了但玩家不知道为什么」。这三条判定的价值不在于最优，而在于**可播报**——战斗日志打一行字，玩家立刻建立「原来它会看场上情况」的心智模型。保底轮换是给手感兜底：连出三个咒火灵，玩家只会觉得系统坏了。

**上限与替换**：场上同时最多 **2 个**召唤物；第 3 次召唤时移除存在最久的那个（带消散 VFX，不静默删除）。理由：上限 2 既保住「铺场」的体感，又挡住深层 30+ 层时召唤师刷屏导致的可读性崩坏与帧率问题（配合美术 §7.4 的低成本像素模板）。

> `[PLACEHOLDER · 三类属性系数与持续时间]` **假设**：召唤师 INT 在 20 层时约 120–150。**验证路径**：Monte Carlo 统计三类召唤物各自的「存活期内造成伤害 / 承受伤害」占队伍总量比例，目标是三类各自占比落在 8%–18% 区间；若石魂卫承伤占比 > 25%，说明它在替代真坦克，需把 HP 从 220% 降到 180%。

### 5.3 属性系统（一级 → 二级转化）

**一级属性（4 个）**：强壮、力量、敏捷、智力。所有二级属性均由这 4 个一级属性按系数转化而来。

| 一级属性 | 代号 | 主要驱动 |
|---|---|---|
| 强壮 | CON | 生命上限、物理/魔法减伤、治疗量 |
| 力量 | STR | 物理伤害、物理暴击伤害 |
| 敏捷 | AGI | 攻击速度、闪避、移动速度、暴击率 |
| 智力 | INT | 魔法伤害、魔法暴击伤害、控制时长、召唤物属性 |

**二级属性（7 个，由一级转化）**：物理伤害、魔法伤害、攻击速度、闪避、移动速度、暴击率、暴击伤害。

**转化公式（示例系数，可在数值表中调参）**：

```
设一级属性为 CON/STR/AGI/INT（含装备/遗物加成后的最终值），基础值 Base。
设体型系数为 B_hp / B_ms / B_size / B_dod（见 §5.2.1），星级系数 S（见 §5.7）。

一级属性最终值 = (基础值 × S_attr + 成长 × 层数 + 装备/遗物) 
              其中 S_attr = 1 + 0.18 × (star − 1)          ← v1.4 升星

生命上限   HP    = (Base_HP + CON × 10) × B_hp             ← v1.4 体型
物理伤害   P.DMG = Base_P  + STR × 2.0  + CON × 0.3
魔法伤害   M.DMG = Base_M  + INT × 2.0
攻击速度   AS    = Base_AS + AGI × 0.4%      （设上限 200%）
闪避率     DOD   = AGI × 0.25% + B_dod       （设上限 75%）   ← v1.4 体型
移动速度   MS    = (Base_MS + AGI × 0.3%) × B_ms（设上限 +60%）← v1.4 体型
暴击率     CRIT  = Base_CR + AGI × 0.2%      （设上限 75%）
暴击伤害   C.DMG = 150% + STR × 0.5% + INT × 0.5%   （物理/魔法按对应主属性加权）
受击半径   R_hit = tile × 0.42 × B_size                     ← v1.4 体型

减伤（坦克向，扩展）：
物理减伤   P.RE  = f(强壮, 物理坦克特质)   上限 75%
魔法减伤   M.RE  = f(智力, 魔法坦克特质)   上限 75%
治疗量     HEAL  = Base_Heal + INT × 1.5 + CON × 0.5
```

**设计要点**：
- 每个二级属性都有**唯一主来源**（如物理伤害只吃力量），保证堆属性有清晰预期，避免「全属性都加一点」的模糊养成。
- 暴击伤害由力量/智力共同贡献，使物理/魔法流派各自有暴击成长路径。
- 敏捷是「手感类」属性的聚合点（攻速/闪避/移速/暴击），对应射手、冲锋物理等高机动职业。
- 所有百分比类二级属性设**软上限**，防止后期数值溢出（配合第 6 节安全边界）。
- 各职业主属性偏向见 5.2，确保 9 个子类在属性获取上形成差异化构筑。

**v1.4 的两个新乘子如何介入（顺序很重要）**：

| 乘子 | 作用位置 | 为什么放这里 |
|---|---|---|
| 星级 `S_attr` | 作用在**一级属性**上 | 升星是「这个人本身更强了」，让它穿透整条转化链自然放大所有二级属性。若直接乘二级属性，会出现「升星加了血却没加暴击」的割裂感 |
| 体型 `B_*` | 作用在**二级属性**上（HP / 移速 / 闪避 / 体积） | 体型只该改这三件事（§5.2.1 约束）。若放到一级属性上，巨躯会连带加物理伤害，直接破坏「体型不改伤害」的红线 |

> **两个乘子相乘的极端值自查**：5 星巨躯 = `1.72 × 1.35 = 2.32×` 有效生命，1 星精巧 = `1.00 × 0.75 = 0.75×`，队内跨度 3.1×。这在坦克↔奶妈的定位差里是可接受的（坦克本来就该比奶妈厚 3 倍）。**红线**：不允许同时给体型和星级再叠一个「品质/稀有度」第三乘子——三个乘子相乘必然通胀，这是所有养成游戏的经典死法。

### 5.4 战斗系统（自动战斗 + 半即时干预）

> 参考角斗士公会经理「布阵后自动演算、看策略结果」的框架，叠加轻量手动干预提升爽感与操作空间。

| 维度 | 设计 |
|---|---|
| 战斗方式 | 自动战斗为主；玩家可在 CD 就绪时手动释放大招 / 切换集火目标 |
| 胜负判定 | 敌方全灭 = 胜；我方全员全灭 = 负（本局结束） |
| 仇恨/集火 | 基于站位与威胁值的 AI 索敌，玩家可「嘲讽/标记」干预 |
| 战斗回放 | 战斗过程可视化（技能特效、伤害飘字、血条），支持 2×/4× 加速与跳过 |
| 数值透明 | 战前显示敌我关键数值对比，降低「被数值暗杀」的挫败 |

> **【v1.3 视觉差异化硬要求】**
> - **技能动画形状差异化**：9 个子类签名技在战斗中的释放特效必须是**可辨识的不同几何形状**（环 `ring` / 泡 `bubble` / 新星 `nova` / 光束 `beam` / 拖尾 `trail` / 牢笼 `cage` / 裂隙 `rift` / 光点 `light` / 冲击波 `shock`），**不得全部用同一种圆圈/直线表现**。形状映射见美术 §7.3，实现于 `src/render/ArenaCanvas.tsx` 的 `Effect.shape` 分支。
> - **像素剪影形状差异化**：9 个子类在 Canvas 上必须有**各自独立的像素剪影轮廓**（不只是换主/辅色），例如坦克=宽盾方块、法师=宽檐长袍、狙击=尖帽长靴、召唤师=兜帽+脚下召唤阵。模板见美术 §4.4，实现于 `src/render/sprites.ts` 的 `TEMPLATES`。

> **【v1.4 技能风格与施法距离硬要求】**
>
> v1.3 解决了「技能长什么形状」，但没解决「技能够多远」。当前所有技能特效都是固定 40px 左右的尺寸，结果是**狙击手 9 格外的一发致命狙击，和魔战士贴脸 2.5 格的爆发，在屏幕上看起来一样大**。这是一个反馈通道故障，不是机制问题——玩家抱怨"技能没差别"时，八成先坏在这里。
>
> **① 每个技能必须声明两个字段**
>
> | 字段 | 类型 | 说明 |
> |---|---|---|
> | `skillStyle` | 枚举 | 技能的动作语言，决定动画三段的编排（9 种，见下表） |
> | `castRange` | number（格） | 实际施法距离，**同时驱动逻辑判定与特效尺寸**，不允许逻辑和视觉用两个数 |
>
> **② 技能风格枚举（9 种，与 9 子类一一对应）**
>
> | `skillStyle` | 中文 | 动作语言 | 对应子类 |
> |---|---|---|---|
> | `bulwark_taunt` | 立场·嘲讽 | 顿地 → 环形外扩 → 仇恨连线 | 物理坦克 |
> | `bulwark_shield` | 立场·护盾 | 能量内缩汇聚 → 护罩成型脉动 | 魔法坦克 |
> | `charge_dash` | 突进 | 后拉蓄力 → 高速位移拖尾 → 落点斩击 | 冲锋物理 |
> | `melee_burst` | 近身爆发 | 双刃交叉 → 原地放射新星 | 突袭魔战士 |
> | `projectile_volley` | 弹幕齐射 | 炮口连闪 → 多发错时弹道 → 落点小爆 | 枪炮手 |
> | `precision_beam` | 精准射线 | 预警细线 → 瞬时激光 → 残线滞留 | 狙击弓手 |
> | `zone_control` | 区域控制 | 地面阵展开 → 牢笼升起 → 顶部锁扣 | 控制型 |
> | `summon_rift` | 召唤裂隙 | 地面裂开 → 召唤物爬出 → 裂隙闭合 | 召唤师 |
> | `blessing_field` | 祝福光场 | 头顶光柱 → 光点飞散全队 → 落点治疗符 | 奶妈型 |
>
> **Boss 技复用规则（v1.4 补漏）**：Boss 技**不新开枚举**，从上表 9 种里复用——践踏 = `bulwark_taunt`(3.5/short)、吞噬 = `zone_control`(8.0/long)、分裂 = `summon_rift`(0/self)。理由是玩家已经用 9 个签名技学会了这套视觉词汇，Boss 复用等于认知直接迁移；Boss 的压迫感应该来自数值和尺寸，不是来自玩家看不懂。映射表与实现细则见美术 §7.2.1。
>
> **③ 施法距离必须在屏幕上可见——三件套（全部为硬要求，不可裁剪）**
>
> | 手段 | 规格 | 解决什么 |
> |---|---|---|
> | **起手距离环** | 施法瞬间在施法者脚下画半径 = `castRange × tile` 的**虚线圆**，持续 0.25s、透明度 0.35→0 | 让玩家一眼看到「这技能能够多远」。0.25s 是不打断节奏的最短可辨识时长 |
> | **特效尺寸随距离缩放** | 所有技能特效的主尺寸 = `f(castRange)`，禁止硬编码固定 px | 距离感来自尺寸本身。远程的光束就该长，近战的斩击就该短 |
> | **命中反馈按档位分级** | 见下表 4 档 | 同样是"打到了"，不同距离的打击语言必须不同 |
>
> **④ 施法距离四档位与各自的视觉语言**
>
> | 档位 | 代号 | 格数 | 命中反馈语言 | 本作使用者 |
> |---|---|---|---|---|
> | 自身 | `self` | 0–1.5 | 特效不离身，原地脉冲，无飞行段 | 魔法坦克 |
> | 近程 | `short` | 1.5–3.5 | 前向扇形/放射，特效前伸 ≤ 1 身位，**无飞行段**（瞬时） | 物理坦克 3.0、魔战士 2.5 |
> | 中程 | `mid` | 3.5–6.5 | 完整「发射 → 可见飞行体（带拖尾）→ 命中」三段，飞行耗时 0.15–0.3s | 冲锋 6.0、枪炮 6.0、控制 6.0、召唤 5.0、奶妈 5.0 |
> | 远程 | `long` | 6.5–10 | **先画 0.2–0.25s 预警线**再瞬时命中，命中后残迹滞留 0.4s | 狙击 9.0 |
>
> > **为什么远程用「预警线 + 瞬时」而不是慢速飞行体**：9 格外的飞行体要么快到看不见，要么慢到不像狙击。预警线把「瞄准」这个动作视觉化了，瞬时命中保住了狙击的干脆感——这是所有做得好的狙击手感的通用解法（剥掉品类外壳看，它和 FPS 的红色激光瞄准是同一个内核：**先告知，再兑现**）。
>
> **⑤ 实现落点**：`SkillDef.skillStyle` / `SkillDef.castRange` 定义于 `src/types.ts`；施法距离判定与特效发射在 `src/game/engine/battle.ts` 的 `castSkill`；三件套渲染在 `src/render/ArenaCanvas.tsx` 的 `drawEffect`。完整风格 × 距离映射表见美术 §7.1 / §7.3。

### 5.5 挑战杯 / 赛制系统

- 分段赛制（见 4.2），每段有独立积分与奖励倍率。
- 每层提供**敌人预览**与**环境预告**，让玩家有「决策信息」而非纯赌博。
- 每层结算发放：遗物 ×1（随机三选一）、金币、天赋点。

### 5.7 层间商店、装备养成与英雄升星（v1.4 重构）

#### 5.7.1 三货架商店

层间休整屏的商店从「装备 + 招募两块」重构为 **三条独立货架**，每条服务一种资源转化决策：

| 货架 | 库存 | 每层刷新 | 决策问题 |
|---|---|---|---|
| **装备架** | 4–6 件（普通为主，深层提高蓝/橙权重） | 是 | 「补强度」——现在就变强 |
| **消耗品架** | 3–4 种（药水 §8 + v1.4 新增稳固药剂） | 是 | 「买保险」——降低下一层的方差 |
| **英雄架** | 2–3 名（**含队伍已拥有的重复角色**，用于升星） | 是 | 「铺人数 or 升星」——本作最主要的构筑决策 |

- **装备**：每名勇者可装备 **6 个通用槽**，提供属性与词条。
- **局内获取**：战斗掉落（3–5 箱/层）、商店购买、出售半价回收（折扣曲线见装备文档 §11.2）。
- **锻造工坊（v1.4 优化，详见《装备与经济设计》§12）**：成功率实时预览 / 蓝装开放锻造 / 追加 gold 成本 / 稳固药剂保护 / 每层 3 次全队共享次数池 / 锻造与合成合并为单一 UI 双 Tab。
- **元进程成长**：账号级装备蓝图解锁，不影响单局平衡（仅扩展可选空间）。

#### 5.7.2 英雄架定价

```
heroPrice = 120 + 40 × (当前队伍人数 − 3) + 60 × (该英雄当前星级 − 1)
```

| 项 | 值 | rationale |
|---|---|---|
| 基线 | 120 | ≈ 4 件普通装备（30/件）。把「招一个人」和「补四件装」放在同一价位上，才构成真决策；低于这个价扩编无脑最优 |
| 人数递增 | +40/人 | 第 7 人的边际价值**高于**第 4 人（人多 = 技能 CD 轮转更密 + 仇恨分摊更广），价格必须跟着涨，否则扩编是免费午餐。7 人时招募价 = 280，是 3 人时的 2.3 倍 |
| 星级递增 | +60/星 | 挡住 1→2→3 星的线性刷脸。凑满 5 星总花费 = 120+180+240+300+360（不含人数项）= 1200 gold，与一件红装同级——这是**深层最重要的 gold sink** |

> `[PLACEHOLDER · 基线 120 与人数系数 40]` **假设**：单局到 20 层累计 gold 收入约 1800–2400。**验证路径**：Monte Carlo 跑 7 人满编 vs 4 人升星两种极端路线到 30 层的胜率；若 7 人路线胜率高出 15% 以上，人数系数从 40 上调到 60。

#### 5.7.3 升星系统（拖拽合并）

**规则**

| 项 | 规格 |
|---|---|
| 触发方式 | 编队界面把**同 `heroId`** 的一名英雄**拖拽到另一名身上**，弹确认框 → 合并 |
| 消耗 | 被拖走的那一名英雄消失（**其装备自动退回背包，不随之销毁**） |
| 星级上限 | 5 星 |
| 属性加成 | 一级属性 × `(1 + 0.18 × (star − 1))`，作用位置见 §5.3 |
| 成长加成 | `growth +1 / 星`（基础 2 → 5 星时 6） |
| 不可逆 | 合并不可撤销，确认框必须显示合并后的完整属性预览 |

**加成 rationale**

- **0.18/星，5 星 = 1.72×**：与「一件橙装约 +25% 单项属性」对齐。满星 ≈ 三件橙装的效果，但它是**全属性**的、且要付出 4 个人头的机会成本。这个兑换率让升星在"值但不无脑"的区间。
- **growth +1/星是关键**：基础属性 1.72× 在 10 层内很香，但 30 层后层数成长项主导，光加基础值会让升星在深层贬值。growth 从 2 → 6（3 倍）保证高星角色在深层持续拉开差距。**这条比 0.18 重要得多**。
- **装备退回而非销毁**：合并的心理门槛已经够高（少一个身位、不可逆），再赔装备就没人敢点了。

> `[PLACEHOLDER · 0.18 与 growth +1]` **验证路径**：跑 500 次 30 层 Monte Carlo，对比「3×5星」「5×3星」「7×1星」三条路线的到达层数分布。目标是三条曲线在 25–35 层区间交叉，即**没有支配解**。若 3×5星 明显领先，0.18 降到 0.12；若 7×1星 领先，growth 加到 +1.5/星。

#### 5.7.4 同名角色多份上场

**允许同一 `heroId` 的多份角色同时出战，不强制合并。**

- 两个 1 星物理坦克 = 两个完全独立的单位，各自的装备、CD、仇恨独立结算。
- **视觉区分**：第 2 份起在名字后缀罗马数字 `II / III`，像素图叠一条辅色臂章（美术 §4.6）。不做这件事的话，编队界面上三个同名同图标的单位会直接把玩家看晕。

**这里存在一个我不打算消解的设计张力，摊开讲**：

| 路线 | 得到 | 失去 |
|---|---|---|
| **升星路线** | 单点强度高，能扛住深层的单次爆发；占位少，站位约束宽松 | 技能 CD 轮转少，队伍总输出窗口窄；一个人被秒 = 损失巨大 |
| **铺人数路线** | 更多技能 CD 同时在转，仇恨分摊，容错高 | 单体强度低，深层会被单次 AoE 一波带走多人 |

我**不给最优解**，也不打算用数值把两条路线拉平到完全等价——那样只会让选择变得无所谓。收敛靠的是**站位上限的物理约束**（前排 ≤ 3 / 中排 ≤ 2 / 后排 ≤ 2，§5.1）：铺人数路线会先撞到排位天花板，被迫开始升星。这是结构性约束，比数值调平更稳、更不需要反复 tuning。

### 5.8 经济系统

| 货币 | 获取 | 消耗 | 作用域 |
|---|---|---|---|
| 金币（局内） | 每层奖励、事件 | 层间商店买遗物/回血/重roll | 单局 |
| 荣誉（元进程） | 单局结算按层数/名次 | 解锁勇者、装备蓝图、外观 | 账号 |
| 赛季积分 | 排行榜名次 | 赛季奖励、段位 | 赛季 |

- **层间商店**：每层间提供 1 次购买/重roll 机会，制造「资源转化」决策（参考指标：金币/伤害比）。
- **经济熔断流**预防：限制单局金币滚雪球，避免后期「买通一切」。

**v1.4 金币 sources / sinks 复核**（任何 source 找不到对应 sink，通胀只是时间问题）：

| Source | 量级 | 对应 Sink | 量级 | 是否抗通胀 |
|---|---|---|---|---|
| 每层胜利奖励 | 随层数线性增长 | 装备架购买 | 30–1200/件，定价固定 | ❌ 后期单价不涨，会溢出 |
| 出售装备（半价回收） | 随掉落量增长 | 消耗品架 | 40–80/瓶，每层消耗 | ⚠️ 稳定但量小 |
| 事件金币 | 一次性 | **英雄架（v1.4 新增）** | 120 → 460/次，**随人数与星级双重递增** | ✅ **主力抗通胀 sink** |
| — | — | **锻造 gold 成本（v1.4 新增）** | `20 + 15×N (+60 蓝装)`，每层可花 3 次 | ✅ 随投入递增 |
| — | — | 合成手续费 | 随 tier 递增 | ✅ |

> **v1.4 之前的通胀漏洞**：装备定价是固定的四档常数（30/120/400/1200），而层奖励随层数增长——数学上必然在某层交叉，过了那一层玩家的金币收入远超商店能吃掉的量，gold 变成无意义的数字。**英雄架是这次修的核心洞**：它的价格随「队伍人数 × 星级」双重递增，恰好在玩家最有钱的深层胃口最大。满编状态下单角色 1★→5★ 累计 `280+340+400+460 = 1480 gold`，7 人全 5 星理论需 **约 10360 gold** —— 一个玩家一辈子填不满的坑，正是无尽模式需要的 sink 形态。详细定价表见《装备与经济设计》§11.4。

### 5.9 排行榜与计分

- **榜单类型**：全球榜 / 好友榜 / 赛季榜 / 单赛季最佳层数。
- **计分公式**（建议）：`总分 = Σ(层积分) × 连胜系数 × 赛季主题加成`，层积分 = f(层号, 剩余血量%, 用时)。
- **防作弊**：服务端校验战斗日志，禁止异常数值（如伤害超过 `2^31−1` 强制归零的硬上限思路）。
- **截图/分享**：战绩卡片一键分享，强化社交比较（留存钩子之一）。

## 6. 数值框架（可执行规格）

### 6.1 难度缩放主公式

```
设层号为 n（n≥1），基准敌人属性 Base：
适应期  (1 ≤ n ≤ 20):
    HP(n)   = Base_HP   × (1 + 0.08·n)
    DMG(n)  = Base_DMG  × (1 + 0.06·n)
复利期  (n > 20):
    HP(n)   = Base_HP   × 1.12^(n−20)
    DMG(n)  = Base_DMG  × 1.10^(n−20)
真空期  (n % 10 == 0):
    HP(n)   ×= 0.60      // -40%
    Speed(n)×= 3.00      // +200%
突变层  (n % 10 == 0, 额外):
    随机应用 1 条混沌规则（持续 1–3 层）
```

### 6.2 三人协作模式难度系数（多人）

> 参考实测：3 人队无尽模式下敌人血量约为单人的 **2.8×**（非 3×），并引入进度差动态平衡。

```
单人基准血量 = H
3 人协作总血量 = H × 2.8
进度差惩罚：若队员历史最佳层数极差 ΔL > 10：
    额外难度 = clamp( (ΔL − 10) × 5% , 10% , 50% )
→ 建议组队成员进度差控制在 10 层内，或让进度最低者任房主
```

### 6.3 数值安全边界

- 单帧伤害硬上限 `2^31 − 1`，超限强制归零 + 全局硬直（防《吸血鬼幸存者》式溢出 bug）。
- 同类型遗物连续 ≥5 次触发「重复疲劳」递减（防同质化 build 崩坏）。
- 伪无尽软上限：60 层后稀有遗物权重递减、敌人组合转实时演算。

## 8. 模式与多人

### 8.1 主模式：单人 · 新手模式（教学战役）→ 通关解锁 · 普通无尽 / 铁人无尽

主模式（单人操控 3–7 名勇者，随进度扩编）由 **三种递进模式** 构成（v2.2 实装，取代 v2.1 的「新手 + 无尽」双模式）：

| 模式 | 封顶层数 | 难度曲线 | 进入条件 | 结算 | 死亡规则 |
|---|---|---|---|---|---|
| **新手模式（Novice）** | 5 层 | 封顶内平缓，到第 5 层胜利即通关 | 默认开放，所有人可进入 | 第 5 层胜利 = 通关，解锁普通无尽 + 铁人无尽 | 阵亡可于下一层满血回归（无永久损失） |
| **普通无尽（Normal Endless）** | 500 层（软上限里程碑 100/200/300/400/500） | 亚线性（平方根）缩放，边际递减，使构筑持续有效 | **新手模式通关后解锁** | 第 500 层胜利 = 无尽登顶；中途全灭 = 失败结算 | 阵亡自动复活，无永久损失 |
| **铁人无尽（Ironman Endless）** | 500 层（里程碑同上） | 同普通无尽 | **新手模式通关后解锁** | 同普通无尽 | **永久死亡（permadeath）：战斗中阵亡的勇者副本从队伍永久移除、装备卸回背包，不可复活** |

**核心规则**

- `RunState.mode: 'novice' | 'normal' | 'ironman'` 记录本局所属模式；`selectedMode` 是跨局的玩家偏好（主菜单选择，reset 不清除）。
- 新手模式为 5 层有限教学战役；到达封顶并胜利即视为「通关」，触发 `endlessUnlocked = true`（localStorage 持久化 `ia_endless`），**同时**解锁普通无尽与铁人无尽。
- 普通无尽 / 铁人无尽未解锁时，`startRun` 强制回退到新手模式（安全护栏，防脏存档进入不存在的模式）。
- 主菜单与编队界面显示当前所选模式；两种无尽模式未解锁时入口灰显并提示「通关新手模式 5 层解锁」。
- 结算界面按 `lastResult.mode` 区分文案：新手通关展示「🎉 已解锁普通无尽与铁人无尽」CTA；无尽登顶展示「登顶 500 层」战绩。
- 难度缩放保持亚线性（§4.3 / 开发 §6.4 `scaling.ts`），`capFor(mode)` 返回对应封顶（`NOVICE_CAP=5` / `ENDLESS_CAP=500`）。
- **新手弹窗教学**：仅在新手模式触发，5 层 × 2 个教学点（共覆盖 6 个核心操作：角色升星、角色卖出、装备合成、装备重铸、商店购买、商店刷新，第 4/5 层补充进阶提示）。每个教学点以云朵型气泡 + 指向箭头锚定到界面真实元素（见 §8.1.1 / 美术 §4.8）。

#### 8.1.1 铁人无尽 · 永久死亡（permadeath）

- 战斗中阵亡的友方副本（含其装备）由 `BattleSim.deadAllies` 记录 `heroUid`；胜利后 `BattleScreen.onEnd` 调用 `store.removeDeadAllies(uids)` 永久移除该副本，并把其穿戴装备卸回背包。
- 普通无尽不调用 `removeDeadAllies`，阵亡勇者自动满血复活，单局内零永久损失（`removeDeadAllies` 守卫始终保留 ≥1 名，避免误清空）。
- 永久死亡只影响「副本」：模板英雄与未上场副本不受影响，可再次招募同名身体。

### 8.2 协作模式：3 人联机

- 每玩家操控 1 名勇者，共享小队站位与羁绊。
- 专用难度系数（6.2）。
- 同步：状态同步 + 战斗演算服务端校验，防作弊。

### 8.3 其他可选模式（二期）

- **竞速模式**：固定层数（如 30 层）比时间。
- **天象挑战**：强制某赛季诅咒，冲分专用。
- **镜像赛**：与历史最强阵容 AI 对战。

### 8.4 角色特性分离（per-instance variation，v2.1 实装）

**需求**：即使是同一个角色（`heroId` 相同），每次上场的个体在 **基础属性（basePrimary）与 体型（bodyType）** 上也会不同——契合「千人千面」的肉鸽体验，也呼应「三名勇者都是独立个体」的设定。

**实现要点**

- 个体差异化只在「副本生成层」（`store.startRun` / `store.recruit`）施加，模板本身（`HEROES`）保持纯净、可复现（保证 smoke / integration 等无头测试稳定）。
- `variateHero(hero, seed)`（`src/game/content/variant.ts`）：以 `{heroId, seed}` 为确定性随机源，对基础属性做 ±幅度抖动、对体型做加权随机抽取，输出带独立 `basePrimary` / `bodyType` 的个体副本。
- 差异化必须真实进入战斗：`makeAlly` 直接读取 `hero.basePrimary` 与 `hero.bodyType`，因此同一 `heroId` 的不同个体在面板与实战中 HP / 体型判定均不雷同。
- 同名多份（§5.7）与特性分离正交：前者解决「同一角色上多份」，后者解决「每份长得还不一样」；两者叠加 = 三份同名角色可能三种体型三种面板。

## 17. v1.7 新需求对齐说明

> 来源：用户新需求（4 条）。落地版本 **v1.7**。配套开发文档 §12、装备与经济设计 §9 / §11.6。
> 设计原则：四条新需求全部**只扩展、不破坏**既有养成（升星/突破/锻造/合成照旧），并以「按实例（uid）记账」为统一底座。

### 17.1 同角色可多份上场 + 出售（需求 1）

- **实例化底座**：队伍中每个成员携带唯一 `uid`；模板 `HEROES` 不带 `uid`。装备（`equipped`）、永久成长（`growthBonus`）、升星/突破（`upgradeHero`）、出售（`sellHero`）**全部按 `uid` 记账**，因此同名多份互不影响。
- **同名多份**：允许同一 `heroId` 的多份同时上场，第 2 份起用**罗马数字后缀 + 臂章像素**区分（美术 §4.6）。视觉/数值完全独立结算。
- **招募解耦升星**：v1.7 起「重复招募」= **新增一份副本**（带独立 `uid` / `dupIndex`），**不再升星**；升星与五星突破改走 `upgradeHero(uid)`，使「变强」与「要多一具身体」成为两个独立抉择。
- **出售**：`sellHero(uid)` 按**招募价 × 星级系数**折算返还金币，卸下的装备回背包；**至少保留 1 名**勇者（禁止卖空）。不需要的副本可随时变现，盘活阵容调整。

### 17.2 击杀敌方永久成长（需求 2）

- **归因**：战斗引擎在击杀敌方单位时，将击杀者归因到其所属英雄实例 `uid`（反弹/魔刃等间接击杀同样归因到反弹/斩杀来源）。
- **成长公式**（每次击杀，永久累积到该副本 `growthBonus`）：
  - 随机 1 项**核心属性 +0.5**（con/str/agi/int）。
  - 随机 1 项**非百分比二级属性成长 +1%**（hp / pDmg / mDmg / heal；**百分比类二级属性——atkSpeed / crit / critDmg / dodge / moveSpeed——不参与**，避免与装备百分比乘区叠加滚雪球）。
- **写回**：战斗结束 `commitGrowth(sim.getKillGains())` 把本场所有击杀成长写回对应副本；下一场通过 `makeAlly → applyGrowthPct` 结算。这是继升星/突破后的第三条**永久养成线**，且与「铺人数」形成正反馈（更多上场副本 = 更多击杀归因点）。

### 17.3 宝箱数量与掉落分布（需求 3）

- **箱数按关型**：普通小关 **3–6 个**基础箱；**Boss 关（每 5 层）8–12 个**基础箱（`chestCount`）。
- **每箱掉落分布**（合计 100%）：

  | 类型 | 占比 | 内容 |
  |---|---|---|
  | 普通装备 | **40%** | 1 件普通装备 |
  | 少量金钱 | **20%** | 约 1–2 层基准金 |
  | 高级装备 | **20%** | 1 件蓝/橙装备 |
  | 稀有装备 | **10%** | 1 件红装 |
  | 大量金钱 | **10%** | 约 4–7 层基准金 |

- **结构**：`pendingDrops` 由 `Equipment[]` 改为 `Chest[]`，每箱 `kind` 决定开箱后落装备还是金币，开箱（`openDrop`）才结算。

### 17.4 装备商店一次性物品（需求 4）

- **翻牌机制**：装备架 **8 个货位**中，每个货位独立以 **20% 概率**翻转为一次性物品（逐位判定，非固定数量，玩家无法背板）。
- **两种一次性物品**（购买 → `consumables` 背包 → 对指定副本使用 → 用后移除）：

  | 物品 | 效果 | 生效 |
  |---|---|---|
  | **成长药剂** | 随机核心属性 **+0.5**、随机二级属性成长 **0.5%~2%**（永久） | 立即写入副本 `growthBonus` |
  | **爆发药剂** | 主属性增强 **+50%**，持续 **1 回合** | 标记 `pendingBurst`，进入战斗消耗，下一场生效 |

- **定位**：成长药剂是「买药」的**永久养成线**；爆发药剂是「下一层搏一把」的**方差保险**，1 回合短窗口避免长期滚雪球。

### 17.5 验收口径（v1.7）

- 同 `npm run integration` 的 [8]–[11] 分组：多份上场 + 出售、击杀成长写回、宝箱数量/分布、商店 20% 一次性物品与药剂效果，全部断言通过；`npm run verify`（typecheck + smoke + integration）绿灯。

## 18. v2.6 新需求对齐说明

### 18.1 教学初始装备包（需求 #1）

- **目标**：新手开局即给到可直接上手的经济素材，避免「空手进教学、看不懂合成/附魔/刷新」。

### 18.2 五星国风坐骑（需求 #2）

- **目标**：角色达到 **5★** 解锁坐骑，强化视觉辨识与战力，坐骑技能独立于英雄技能 CD。
- **规格**：5★ 时 `rollMount` 从 `{战象, 玄豹, 猛虎, 赤兔, 青牛}` 随机解锁一种，写入 `HeroDef.mount` 与 `Unit.mount`；坐骑拥有**独立 CD 技能**（`mountCd`，独立于 `skillCd`），由 `castMountSkill` 触发。
- **坐骑技能（贴合性情）**：战象=践踏震慑（范围减速/控制）、玄豹=迅袭连爪（高频多段）、猛虎=虎啸威压（范围破甲/恐惧）、赤兔=赤兔冲阵（直线突进击退）、青牛=蛮牛顶撞（单体重击击退）。
- **表现**：像素侧视 24×14 分层渲染（骑手坐于背脊、整组按 `facing` 镜像）；技能就绪时脚下呼吸辉光；详见美术 §10.1。
- **验收**：`check-templates` 校验 5 套坐骑模板行宽一致；5★ 单位 `mount` 非空且 `mountCd` 正常递减、技能触发不占用 `skillCd`。

### 18.3 敌方补给建筑（需求 #3）

- **目标**：地图随机刷敌方补给建筑，要求玩家「权衡拆除」，否则高风险——拆光建筑会被已产出的兵拖垮，反之建筑持续产兵。
- **规格**（随机站位、合理分布，计敌方胜利条件）：
  - 军帐 barracks：产普通兵，本场上限 **8**。
  - 木塔 / 石塔 / 铁塔：远程造成伤害，塔上各驻 **1~2** 守兵；铁塔熔炉口发光。
  - 龙巢 dragon_nest：产幼龙（Boss 幼体），上限 **3**。
  - 龙穴 dragon_lair：额外 **+1 成年龙 + 4 幼龙**。
- **表现**：自有配色 + 红地基环（不吃红染）；`hpFrac` 驱动结构受损与濒危余烬；`spawnTimer<1.5s` 顶部产兵预警脉冲。详见美术 §10.2。
- **验收**：`tickBuilding` 产兵受各 `cap` 限制、塔走 `basicAttack` 远程伤害；建筑计入敌方胜利计数（拆光≠胜利）。

  - 普攻轨迹（lighter 加色，0.32s 窗口内扫出）：武圣月牙弧、剑客竖直快剑+尖端亮点、炮手枪口火花+放射线、后羿箭轨细线、玄武盾击横线+盾环、符甲符箓上扫曲线、太极推掌圆波、药杖/法杖杖头光点。

  - 受击：`flash>0` 时后仰 + 55Hz 高频短抖（血条不跟抖，保持可读）。

- **验收**：`npm run typecheck` 零错误；`npm run verify` 四道闸门全绿（含 [15]–[18] 回归）；本地 Vite dev 实机目验各职业待机/挥砍/施法/倒下观感。
