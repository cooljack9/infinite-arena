# v1.5.0 本地版 · 响应速度与战斗预载优化（计划 + 评估）

> ⚠ **版本体系已统一**：本仓自 **v2.0.0** 起收敛为**单一版本基线** —— `package.json`、`CORE_VERSION`、git tag、压缩包、线上 Pages、全部文档共用唯一版本号 `2.0.0`。本文标题与正文中出现的其它 `vX.Y.Z` 均为**历史里程碑代号**，不再具有发布号效力（详见 `docs/INDEX.md`「版本体系」）。

> 版本线：本地版走 `X.Y0`（见 CICD.md §8）。本版在 v1.4.0 之上做一轮「等待时长」专项优化，纯前端/渲染层 + 计时改动，**零 `packages/core` 确定性引擎改动**。

## 一、用户反馈（原话要点）

1. 大部分等待太长，严重拖累体验；实测数据传输都在 **500ms 以内**。因此**所有前后端交互的响应时间统一压到 1.25 秒**（3 秒有明显卡顿，超过 1.5 秒就会有不流畅感）。
2. 战斗时不应「三句话说完才开始载入战斗动画」——应当在**传参完成那一刻就完全载入战斗引擎**，三句话说完直接开打。

## 二、等待盘点（当前所有 >1.25s 的人为延迟）

| 位置 | 原值 | 性质 | 归为「前后端交互响应」？ |
|---|---|---|---|
| `IntermissionHub.tsx` 开箱×2 / 招募刷新 / 招募 | 3000ms | `fxBusy` 锁（模拟服务端处理） | ✅ 是 |
| `ForgeTab.tsx` 重铸 / 融合 | 3000ms | `fxBusy` 锁 | ✅ 是 |

## 三、统一标准

- **所有「前后端交互响应时间」上限 = 1250ms**（1250 < 1500，规避"不流畅感"阈值）。
- 上表 ✅ 项全部收敛到 `1250`；⚠️ 叙事类（出征台词）从 4s 压到 2.5s（仍偏长但属叙事节拍，可调）；开战三段过场从 3s 压到 ~1.26s（3×420ms），既满足 1.25s 上限、又保留"三句话"播完即开打。

## 四、战斗引擎预载设计（核心改动）

### 现状（痛点）
`PreBattle.confirm()` → 三段过场倒计时（3s）→ `setScreen('battle')` → `BattleScreen` 挂载 → 显示「⏳ 战斗加载中…」加载门 → 首帧 paint 后 `requestAnimationFrame` 才构造 `BattleSim`。即**三句话说完才开始构造引擎**，中间多一道加载门。

### 目标
传参（布阵确定 `formation` + 点「确认开战」）那一刻，**后台（rAF）就把 `BattleSim` 构造好并缓存**；倒计时三句话播完、`BattleScreen` 挂载时直接消费缓存，**不再有加载门**。

### 实现（零引擎改动）
1. **新建 `src/game/battleBuild.ts`**：把 `BattleScreen` 现有的 sim 构造逻辑（本地分支 + 远程 replay 分支）原样抽成 `buildBattleSim(run, plan, equipped, formation, battleRemote)`。
2. **预载缓存**：同模块导出
   - `preloadBattleSim(...)`：`isRemoteMode()` 时直接 no-op（远程 replay 由 `BattleScreen` 异步拉取，无法预载）；本地模式用 `requestAnimationFrame` 后台构造并写入模块级 `pendingSim`（try/catch 兜底，失败回退运行时构造）。
   - `consumeBattleSim()`：取出并清空缓存（消费一次）。
   - `clearBattlePreload()`：进入布阵页时清残留，防跨层吃到上一场 sim。
3. **`PreBattle.confirm()`**：`setFormation(form, preset)` 后 `requestAnimationFrame(() => preloadBattleSim(run, plan, equipped, form, battleRemote))`——倒计时启动与引擎构造并行，三句话播完时引擎已就绪。
4. **`BattleScreen`**：挂载时用 `consumeBattleSim()` 初始化 `sim` 状态 → 预载命中则**无加载门**直接开打；未命中（远程模式/预载异常）走原有 rAF 兜底（远程模式这是真实网络往返，加载门保留合理）。

### 为何零确定性风险
- `buildBattleSim` 与现有构造逻辑**逐行一致**，随机数全部来自 `run.seed + run.layer`（确定性），不引入任何新随机源。
- 预载只是"提前构造同一个 sim 并缓存"，构造结果=进入战斗时本应构造的结果，回放/结算种子不变 → 21/21 后端契约与确定性守卫不受影响。
- 远程模式不预载，保持原权威回放流程。

## 七、执行结果（2026-08-09）

### 改动清单
- **新增 `src/game/battleBuild.ts`**：`buildBattleSim`（与 BattleScreen 原构造逐行一致）+ `preloadBattleSim` / `consumeBattleSim` / `clearBattlePreload` 预载缓存。
- **`BattleScreen.tsx`**：挂载即用 `consumeBattleSim()` 初始化 sim，预载命中即**无「⏳ 战斗加载中…」加载门**；远程模式走原 rAF 兜底；清理已抽离的导入。
