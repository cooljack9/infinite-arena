# v1.6.0 本地版 · 前后端查表查询精简计划

> ⚠ **版本体系已统一**：本仓自 **v2.0.0** 起收敛为**单一版本基线** —— `package.json`、`CORE_VERSION`、git tag、压缩包、线上 Pages、全部文档共用唯一版本号 `2.0.0`。本文标题与正文中出现的其它 `vX.Y.Z` 均为**历史里程碑代号**，不再具有发布号效力（详见 `docs/INDEX.md`「版本体系」）。

> 范围：仅重构「请求/响应胶水层」与「后端 Supabase 查询层」，确定性引擎 `packages/core` 零改动。
> 目标：把“写得太长、过于分散”的查表查询统一成简短精炼的形态，且**不改动任何下发数据的字段形状**（前端与 21 项后端契约都依赖这些 DTO）。

---

## 1. 背景与目标

用户反馈：前后端“查表”相关的查询很多写得太长，希望统一构建出来的查询尽量简短精炼，且不要把数据搞复杂。

经排查，真正的“查表查询冗长”集中在三处（均不在确定性引擎内）：

| 层 | 文件 | 症状 |
|---|---|---|
| 前端命令胶水 | `src/backend/RemoteBackend.ts` | 22 个近乎逐字重复的 `callOr('action', req, (b)=>b.xxx(req))` 方法；`callOr` 内部 `_localFn` 参数自 v3.4h 降级移除后已是死代码 |
| 后端命令胶水 | `supabase/functions/game/index.ts` | `dispatch` 用 33 行 `switch` 逐个路由 25 个命令 |
| 后端查询层 | `supabase/functions/_shared/db.ts` | `saveRun` 用 `(q.select as unknown as ...)('id',{count,head})` 强转 hack；`loadRun` 把取到的结果逐字段再映射一遍（冗余） |

`LocalBackend.ts` 已通过 `mutate()` 统一了「读→规则→存回」形状，本身够 DRY，**本次不动**。

---

## 2. 精简策略（Shape 冻结纪律）

**铁律：所有下发到前端的 DTO 字段名/结构保持不变。**
- `queryMeta / queryRun / queryBattlePlan` 返回值不变。
- `handleBattle` 的 `replay{}` / `outcome{}` 字段名与嵌套结构原样保留（这些是前端 `battleRemoteOf` / `battleBuild` 的依赖项）。
- `db.ts` 的 `RunRow` / `BattleRow` 列集不变。

只做**结构性精简**：删死代码、收口重复、用更短的等价写法。不引入任何新字段、不改字段名、不改枚举值。

---

## 3. 执行步骤

### 3.1 `src/backend/RemoteBackend.ts`（前端，受 tsc 覆盖）
- 删除 `callOr<T>(...)` 方法（`_localFn` 已是死参数，内部只转调 `call`）。
- 22 个方法从 `return this.callOr('x', req, (b)=>b.x(req))` 收敛为一行 `return this.call<T>('x', req);`；`startRun` 保留 `debugSeed` 剥离特例。
- 预计从 ~275 行降到 ~90 行，行为逐字节等价（`callOr` 本就是 `call` 的透传）。

### 3.2 `supabase/functions/_shared/db.ts`（Deno，@ts 严格）
- `saveRun`：去掉 `(q.select as unknown as ...)('id',{count:'exact',head:true})` 强转，改为链式 `.select('id')` 后判定 `Array.isArray(data) && data.length > 0`（与注释记载的“用 data.length 判定”意图一致，且更短）。
- `loadRun`：去掉冗余的逐字段 `return { id, version, ... }` 映射，直接 `return (data as RunRow)`（`data` 已含所选列）。
- `loadBattle` 的 `.select('*')` 维持（已是最短写法，且“不要过度复杂化”正是不必展开列）。

### 3.3 `supabase/functions/game/index.ts`（Deno，@ts-nocheck）
- `dispatch` 的 33 行 `switch` 收敛为一张 `HANDLERS: Record<string, (p, ctx) => ...>` 命令表 + 4 行查表分发。
- 各 handler（`handleStartRun / handleBattle / handleAck / handlePlan / handleParity / skipLayerSafe / mutate` 等）**函数体原样保留**，仅注册进表，确保输出形状 100% 不变。

## 4. 验证方案

| 验证项 | 命令 | 覆盖 |
|---|---|---|
| 前端语法/类型 | `npm run build` | RemoteBackend 改写后的 TS 类型与构建 |
| 全链路本地 | `npm run verify` | typecheck → check-templates → guard(确定性) → smoke → integration → backend（21 契约 + 确定性守卫全绿） |
| Edge 函数语法 | `node --check supabase/functions/game/index.ts` 与 `node --check supabase/functions/_shared/db.ts` | Deno 文件语法闸门（本地无 Deno，仅做解析校验） |
| HTTP/DTO 奇偶 | `npm run mock:edge` + `npm run e2e:remote` | 经 HTTP 通路验证 DTO 形状与 LocalBackend 逐 bit 一致（mock-edge 为参考实现，本轮不变，理应仍全绿） |

> 说明：本地无 `deno`，`game/index.ts` / `db.ts` 无法在 Deno 运行时跑真实 Postgres 路径；本轮以「语法校验 + 形状逐字节保持 + mock-edge 协议奇偶」三道闸兜底，输出形状与现网完全一致。

## 5. 风险与回滚

- **风险点**：`saveRun` 的 `select` 判定改写若行为不符，会导致乐观锁误判（假 `STATE_STALE`）。已在 3.2 中保持“data.length>0”语义不变。
- **回滚**：全部为胶水层局部改写，若 verify 或 e2e 异常，单文件 `git checkout` 即可还原，不影响 `packages/core` 与已提交版本。
- **交付**：本地 `master` 全量提交 v1.6.0（不推送远端，符合 local 版 CI/CD 规则）。
